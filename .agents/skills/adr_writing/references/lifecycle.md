# ADR 生命周期细则（adr_writing）

新写、取代、条款级修订、挂账与闭合四类动作的执行细则。骨架一律按 [templates/adr.md](../templates/adr.md)。

## 新写

1. 编号与文件名：`NNNN-slug.md`，编号四位连续。**ADR 编号不经项目管理平台**（那是 AXY 编号的规矩）：取 `index.md` 决策日志最大编号 +1。frontmatter 的 `description` 写成可独立检索的一两句。
2. 状态只有「已接受（Accepted）」与「已取代（Superseded）」两种落盘值——草案态留在 design 选型记录或评审里，**落盘即已接受**（批准门由触发场景承载）。
3. 更新 `index.md`：决策日志加一行；属技术栈级、带硬约束的决策，同时在「现行技术栈速查」表加行（技术 + 硬约束 + 需回读全文的信号）。

## 取代（supersede）

1. 新 ADR 状态行写「已接受（Accepted）」，不出现被取代者的编号；背景用事实陈述取代缘由（旧决策造成的现状与痛点，而非引用它）；决策把旧决策中仍然有效的边界**重写为自身条目**，读者不依赖旧文件也能拿到完整的现行约定。
2. 旧 ADR 只改状态行为「已取代（Superseded）」，正文保留原貌——被取代的决策记录仍有历史价值，禁止删除文件（包括被否决的 ADR）。
3. 受牵连的其他 ADR：表述需跟着新决策走的直接修订正文（不留痕，见「条款级修订」），双方正文互不提及。
4. `index.md`：旧行状态列改「已取代（YYYY）」，新 ADR 加行；速查表有旧行的替换为新 ADR 行。取代映射只存在这里。

## 条款级修订

修订本身也是决策，**一律由一篇新 ADR 承载**，不直接改旧文件了事：

- 修订以修订方 ADR 自身的一条正面决策承载：直接写出新约定内容、缘由与缓解面，不指向被修订的文件；
- 被修订 ADR 的条款正文按新条目完整替换（doc_writing 规则 4），状态不变，不留痕；
- 修订动作记在修订方自己的 `index.md` 日志行备注里，被修订方行不动。

## 挂账与闭合

后果或风险节的「后续可……」是显式承诺，不是语气词。新 ADR 闭合某条挂账时，背景第一条把被挂账的事实本身陈述清楚，不引用出处；被闭合 ADR 的该条目同步更新。反向同理：自己写下的挂账，预期它会在未来某篇 ADR 的背景节被重新陈述为事实。
