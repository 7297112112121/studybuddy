# 布局骨架草稿(layout-wireframe)

## 定位

输入为网站截图/图片或网页 URL,输出为 studybuddy UI 草稿工作区(`studybuddyui/`)中一个完整的布局条目。本技能只产出布局骨架:灰色盒子表示布局区域的位置与相对比例,白色文字标注编号与区域名;具体组件、真实文案、图标、配色装饰一律不产出(组件草稿不归本技能)。

草稿工作区的目录约定与 AI 使用约束以 `studybuddyui/README.md` 为准;本技能只新增条目文件并在 `src/App.tsx` 注册,不改其他条目。

## 硬门禁

1. **方案未选定不落盘**:候选布局只以文字描述呈现,开发者明确选定前禁止创建任何文件。
2. **只保存选定方案**:落盘内容仅为开发者选中的那一个布局;候选方案的文字描述看完即弃,不进仓库。
3. **审阅未通过不归档**:`result.png` 在开发者确认布局无误后才生成;有修改意见则回到生成步迭代,归档动作始终在确认之后。
4. **只做布局**:灰盒内不出现组件、表单、图表等内容;标注文字只有编号与区域名。
5. **不碰其他条目**:禁止读取或引用 `components/`、`backgrounds/` 及其他 `layouts/` 条目的代码;需要了解草稿工作区时读 `README.md`。

## 流程(六步)

### 1. 输入获取

- 图片:直接读图。
- URL:用 Playwright MCP `browser_navigate` 打开页面,`browser_take_screenshot` 整页截图,以截图为分析对象。
- 页面打不开(网络/登录墙)时呈报开发者,改为由开发者提供截图;禁止凭 URL 或记忆猜测布局。

### 2. 布局分析(文字方案)

识别页面结构,提出 2-3 个候选布局方案,以文字列表交开发者挑选;方案的骨架类型与动线依据 [布局设计方法](../../../docs/dev/布局设计方法.md) 选择,比例取值用其栅格整数比与核心区域尺寸。每个方案包含:

- 方案名(如「上下结构:顶栏 + 侧栏 + 内容区」);
- ASCII 线框示意图:用方框与缩进画出各区域的相对位置与比例,让开发者在选定前看到大概布局效果;
- 区域清单与层级关系(哪些区域并列、哪些嵌套);
- 与原图的对应关系及取舍理由。

示意图紧随方案名呈现(呈现渠道支持选项预览时放入预览);示意图是对话内的一次性示意,不创建文件(与硬门禁 2 一致)。此步禁止生成任何代码。开发者提出候选之外的方案时,按其描述直接进入下一步。

### 3. 生成布局骨架

开发者选定方案后:

- 目录为 `studybuddyui/layouts/<条目名>/`,目录名即布局名称:kebab-case、概括页面用途(如 `chat-page-layout`);名字拿不准时报开发者确认。
- 条目内组件文件为 `code.tsx`:
  - 根容器背景纯白;
  - 每个布局区域一个灰色盒子(`#D9D9D9`),按原图比例近似占位(侧栏宽度、顶栏高度等用相对比例表达);
  - 盒内居中白色文字,格式 `<编号>、<区域名>`(如 `1、头部栏`),编号按阅读顺序从 1 递增;
  - 禁止具体组件、图标、真实文案、阴影装饰;区域间距按布局设计方法的 8 点栅格取 8 的整数倍。
- 组件 default export、自包含,不导入工作区内任何其他条目。

### 4. 注册与类型自检

- 在 `studybuddyui/src/App.tsx` 的 `DraftKey` 与 `DRAFTS` 中注册新条目(标签用中文概括布局名)。
- 在 `studybuddyui/` 目录跑 `npx tsc --noEmit`。
- 按 [布局设计方法](../../../docs/dev/布局设计方法.md) 的布局校验清单自查(对齐、焦点、层级、间距),通过后再预览。

### 5. 审阅

- 在 `studybuddyui/` 目录启动 `npm run dev`,用 Playwright 打开本地地址并切换到新条目,截图呈报开发者。
- 开发者确认无误 → 第 6 步;有修改意见 → 回第 3 步修改后重新预览(不重复方案分析)。

### 6. 截图归档与 prompt.md

- 用 Playwright `browser_take_screenshot` 把布局截图保存为 `studybuddyui/layouts/<条目名>/result.png`:
  - 截图对象为布局草稿容器本身(element 截图),排除草稿工作区顶部的条目切换导航;
  - 页面重新打开后草稿选择复位到第一个条目,截图前先切换到目标条目。
- 撰写 `prompt.md`,参照 `components/week-view-calendar/prompt.md` 的【角色】【任务】【设计规格】【约束】四段结构:内容为该布局的设计提示词——区域清单、编号与名称、相对比例、灰盒规范;prompt.md 直接描述布局设计,禁止「复现 XX 截图」类字样,不提及来源截图或原页面;禁止把 TSX 代码抄进 prompt.md。
- 关闭 dev server,向开发者报告产物路径清单。

## 产出一览

`studybuddyui/layouts/<条目名>/` 下三个文件,外加 App.tsx 注册:

| 文件             | 内容                       |
| ---------------- | -------------------------- |
| `code.tsx`       | 布局骨架组件(灰盒 + 标注)  |
| `prompt.md`      | 布局设计提示词             |
| `result.png`     | 审阅通过后的布局截图       |

## 合理化对照表

| 借口                                   | 裁决                                                     |
| -------------------------------------- | -------------------------------------------------------- |
| URL 打不开,凭经验直接写布局            | 分析对象必须是真实截图,打不开就找开发者要图(流程 1)     |
| 开发者还没选方案,先把代码写好备用      | 方案未选定不落盘(硬门禁 1)                              |
| 灰盒里放个假表单,看起来更像原页面      | 只做布局,标注文字只有编号与区域名(硬门禁 4)             |
| 顺手把别的条目的样式一起调了            | 不碰其他条目(硬门禁 5)                                  |
| 截图等全部条目做完再批量补              | 归档在每次审阅确认后立即完成(硬门禁 3)                  |
