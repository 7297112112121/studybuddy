# 无参考组件草稿(component-blank)

## 定位

输入为开发者对组件用途的一句话说明,输出为草稿工作区(`studybuddyui/`)中一个真实可交互的组件条目。本技能处理「无参考图」场景:没有截图或 URL 可对照,组件方案来自该类组件的常见模式与 [组件设计方法](../../../docs/dev/组件设计方法.md) 的量化规格。有组件参考截图或 URL 时改用 [component-wireframe](../component-wireframe/SKILL.md);页面级布局骨架归 layout 家族技能。

产物约定与 component-wireframe 完全一致:`studybuddyui/components/<条目名>/` 下 `<条目名>.tsx` + `prompt.md` + `result.png`,目录名即组件名称(条目名 kebab-case,组件 PascalCase)。产出真实组件效果——结构、样式、全部交互状态一次给全。

## 硬门禁

1. **方案未选定不落盘**:候选组件方案只以文字描述呈现,开发者明确选定前禁止创建任何文件。
2. **只保存选定方案**:落盘内容仅为开发者选中的那一个方案;候选方案的文字描述看完即弃,不进仓库。
3. **审阅未通过不归档**:`result.png` 在开发者确认组件无误后才生成;有修改意见则回到生成步迭代,归档动作始终在确认之后。
4. **全状态陈列**:默认、Hover、Active、Disabled 四态缺一不可;扩展态(聚焦/加载/错误/空数据等)按组件类型推演补齐。只画默认好看的样子视为未完成。
5. **通用组件红线**:不写死业务文案与业务数据,一律用通用占位文案;组件脱离具体业务场景后必须仍独立成立。
6. **不碰其他条目**:禁止读取或引用 `layouts/`、`backgrounds/` 及其他 `components/` 条目的代码;需要了解草稿工作区时读 `README.md`。

## 流程(五步)

### 1. 用途澄清

- 以开发者的一句话说明为设计输入;组件用途信息不足以提出方案时(如只说「一个组件」),先向开发者询问使用场景与核心交互,再进入下一步。
- 用途明确后不再追问,不替开发者编造业务需求;拿不准的假设在方案描述中显式写出。

### 2. 组件分析(文字方案)

基于 [组件设计方法](../../../docs/dev/组件设计方法.md) 的典型组件策略与该类组件的常见模式,提出 2-3 个候选方案,以文字列表交开发者挑选。每个方案包含:

- 方案名(如「上下结构:标签 + 输入区 + 底部提示」);
- ASCII 线框示意图:用方框与缩进画出组件内部区块的相对位置与比例,以及状态陈列的编排方式,让开发者在选定前看到大概效果;
- 区块清单与信息层级(核心元素与辅助元素);
- 变体与状态清单:风格变体、尺寸档位、必选四态 + 按组件类型应补的扩展态;
- 适合该组件用途的理由。

示意图紧随方案名呈现(呈现渠道支持选项预览时放入预览);示意图是对话内的一次性示意,不创建文件(与硬门禁 2 一致)。方案之间应覆盖主流模式的实质差异(如「独立触发器 + 浮层」vs「内联展开」、文字输入 vs 图标按钮触发),避免仅粗细粒度不同的三个变体。尺寸取值用组件设计方法的尺寸三档、圆角与内边距规则,在方案描述中直接给出。此步禁止生成任何代码。开发者提出候选之外的方案时,按其描述直接进入下一步。

**动画询问**:呈报方案时一并询问开发者是否需要动画设计;选择需要时加载 [motion-design](../motion-design/SKILL.md),为最终选定的方案按其规范产出动画规格,落实到代码过渡与 prompt.md 动画说明;选择不需要则不加进入/退出编排。

### 3. 生成组件草稿

开发者选定方案后:

- 目录为 `studybuddyui/components/<条目名>/`,条目名即组件名称:kebab-case、概括组件用途(如 `search-input`);组件名为 PascalCase,代码文件为 `<条目名>.tsx`(如 `search-input.tsx` 导出 `SearchInput`);名字拿不准时报开发者确认。
- 产出真实组件效果:结构与样式按选定方案与 [组件设计方法](../../../docs/dev/组件设计方法.md) 实现(尺寸三档、圆角规范、内边距规则、状态样式公式、阴影分层);不写死业务文案,用通用占位文案(硬门禁 5)。
- 全状态陈列:页面内并排陈列全部状态,每组配状态名文字标注;Hover/Active 等瞬态在陈列区以静态样式呈现对应视觉,同时用 `hover:`/`active:` 等伪类实现真实交互;禁用/加载/错误/空态按对应规则直接渲染。
- 组件 default export、自包含,不导入工作区内任何其他条目;样式只用 Tailwind CSS 类,不引入新依赖。

### 4. 注册与类型自检

- 在 `studybuddyui/src/App.tsx` 的 `DraftKey` 与 `DRAFTS` 中注册新条目(标签用中文概括组件名)。
- 在 `studybuddyui/` 目录跑 `npx tsc --noEmit`。
- 按 [组件设计方法](../../../docs/dev/组件设计方法.md) 的组件校验清单自查(状态齐全、规格复用、边界处理、反馈与可访问性),通过后再预览。

### 5. 审阅与归档

- 在 `studybuddyui/` 目录启动 `npm run dev`,用 Playwright 打开本地地址并切换到新条目,截图呈报开发者;审阅以开发者的组件用途预期为准。
- 开发者确认无误 → 归档;有修改意见 → 回第 3 步修改后重新预览(不重复方案分析)。
- 归档 `result.png`:用 Playwright `browser_take_screenshot` 把组件陈列页截图保存为 `studybuddyui/components/<条目名>/result.png`:
  - 截图对象为组件草稿容器本身(element 截图),排除草稿工作区顶部的条目切换导航;
  - 页面重新打开后草稿选择复位到第一个条目,截图前先切换到目标条目;
  - 页面存在持续动画(如加载态 `animate-spin` 旋转图标)时,先用 `browser_evaluate` 向 `<head>` 注入 `*, *::before, *::after { animation-play-state: paused !important; }` 暂停全部动画,再执行截图。
- 撰写 `prompt.md`,参照 `components/` 现有条目的【角色】【任务】【设计规格】【约束】四段结构:内容为该组件的设计提示词——区块清单、状态清单(每个状态的触发方式与视觉样式)、尺寸/圆角/间距/色值等精确数值、交互说明(触发方式、反馈效果、异常流程、动画时长);prompt.md 直接描述组件设计,禁止「复现 XX 截图」类字样;禁止把 TSX 代码抄进 prompt.md。
- 关闭 dev server,向开发者报告产物路径清单。

## 产出一览

`studybuddyui/components/<条目名>/` 下三个文件,外加 App.tsx 注册;产物与工作流步骤一一对应:

| 文件           | 内容                       | 产出时机          |
| -------------- | -------------------------- | ----------------- |
| `<条目名>.tsx` | 组件草稿(真实效果 + 全状态陈列) | 第 3 步生成后落盘 |
| `result.png`   | 审阅通过后的组件陈列截图   | 第 5 步审阅通过后 |
| `prompt.md`    | 组件设计提示词             | 第 5 步审阅通过后 |

## 合理化对照表

| 借口                                      | 裁决                                                     |
| ----------------------------------------- | -------------------------------------------------------- |
| 用途就一句话,自行补全业务细节再出方案     | 用途不足以提方案时先问,不替开发者编造需求(流程 1)       |
| 开发者还没选方案,先把组件写好备用         | 方案未选定不落盘(硬门禁 1)                              |
| 没有参考图,只画默认态撑场面               | 全状态陈列,缺失状态按组件设计方法推演补齐(硬门禁 4)     |
| 三个方案其实是一个组件的三种粒度          | 方案须覆盖主流模式的实质差异(流程 2)                    |
| 文案直接编点业务文案更逼真                | 通用组件红线,用通用占位文案(硬门禁 5)                   |
| 顺手把别的条目的样式一起调了              | 不碰其他条目(硬门禁 6)                                  |
| 截图等全部条目做完再批量补                | 归档在每次审阅确认后立即完成(硬门禁 3)                  |
