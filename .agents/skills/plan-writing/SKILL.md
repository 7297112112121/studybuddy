# 实现计划编写（plan-writing）

## 概述

开发技能组第三步：把已批准的架构设计拆解为**微任务实现计划**。计划写给一个没见过这段对话、但会写地道代码的实现者——他们能做对计划留白处的合理选择，做不对的是你已决定的事：哪些文件、哪些名字与签名、需求里的哪些值、哪些测试证明哪个任务。把这些写下来。

**开始时声明**：「我正在使用 plan-writing 技能为 <特性名> 编写实现计划（档位：轻量/标准/严格）。」

## 触发范围与档位

**不触发**：spike/原型验证、一次性脚本、纯文档或纯配置变更、不产出产品代码的探索。若不确定，按标准档执行，并在计划头注明档位与理由。

**三档选择**（写入计划头部 `Tier:` 行）：

| 档位 | 适用 | 必须做 | 可跳过 |
|---|---|---|---|
| 轻量 | 单文件/低风险/无迁移/无 E2E | 任务卡（文件+签名+失败测试名+提交信息）、先红后绿、证据汇总行 | design 逐节盘点、Review Focus、子代理纪律 |
| 标准（默认） | 一般特性 | 完整流程；Review Focus ≤5 条；子代理默认内联 | — |
| 严格 | 跨模块/迁移/并发/安全敏感/多链并行 | 完整流程 + 全部纪律；Review Focus 可超 5 条但须记裁决 | — |

## 硬门禁（HARD-GATE，对产品代码生效）

**无先失败的测试，即无产品代码。** 单元、集成、E2E、迁移/schema 一律先红后绿；集成与 E2E 是**显式任务**，不是实现后的收尾补写。先写实现再补测试 = 按实现写测试，永远通过但不测边界。

*例外*：spike/原型、一次性脚本、纯文档/配置不在此列；产品代码路径一旦混入原型，按产品代码处理。

## 保存位置

`docs/dev/AXY-<N>-<slug>/tasks.md`（与 design 同目录；proposal 位于 `docs/product/AXY-<N>-<slug>/`，目录名沿用其编号与 slug，日期写进头部 Date 行）。

## 第 1 步：读 design 并盘点

通读**已批准的 design**，逐节盘点为任务原料，不直接按 proposal R 表拆任务。派生规则：

- **契约表**：每个契约（签名 + 调用方/被调方 + 错误情形）至少一个任务；错误情形至少一条失败测试，随签名抄入任务卡 Interfaces 行；
- **数据模型与状态转换**：迁移/schema 任务；每个状态转换至少一个测试任务；
- **UI 与组件**：组件任务；每个演示态至少一个 E2E 任务（任务卡 AC/演示态行必填）；
- **错误与边界（边界表 + E 表映射）**：逐条对应失败测试，呈现位置写进断言；
- **需求承载对照与测试接缝**：每个可测接缝至少一个任务，任务卡「失败测试」行取自接缝；
- **范围与非目标**：逐条摘入「不安排任务」清单，执行期不得临时加任务；
- **开放问题**：假设声明进 Global Constraints 或 Review Focus；
- **ADR 关系**：强约束（版本锁定、端点禁用等）进 Global Constraints。

proposal 是对照源：R 表（状态「废止」不安排任务）、E 表、路由行为表、边界表、演示态清单，用于核对 design 落点无遗漏。**不得只按 R 表拆任务**：design 每条契约、状态转换、错误边界、演示态、可测接缝，都必须有承载任务或明确由哪个任务的哪个测试覆盖。

## 计划结构

按 `templates/tasks.md` 骨架写入：

- **头部**：Goal / Date / Spec / Design / Tier + **Global Constraints**（逐行照抄，值不转述）+ **不安排任务**（design 非目标逐条落名）+ **Review Focus**（默认 ≤5 条，按风险排序；每行必须有测试固定在对应任务）；
- **执行纪律**：全局声明一次 TDD 六步（写失败测试 → 确认失败 → 实现 → 确认通过 → 全量套件 → 提交），任务卡只写差异；
- **裁决记录节**：计划尾部，一行格式，承接执行期偏离。

## 粒度规则

- **任务**：最小可独立携带一个测试循环、值得一次独立审查的单元。脚手架/配置/文档折叠进需要它的任务；只有审查者可能通过一个任务而否决其邻任务时才拆开。
- **步骤**：以 TDD 六步为准，任务卡只写差异（文件、签名、失败测试、预期失败、提交信息）。
- **硬比例规则**：任务卡正文 ≤15 行（不含模板字段行）；**禁止抄函数体**，签名 + 测试名 + 断言三件套足够。超限须在裁决记录写理由——计划比代码长就是写成了转写。

## 集成与 E2E 任务

单元任务之后安排独立集成/E2E 任务，先红后绿：先写失败用例（对应 proposal 验证方式标「集成测试 / E2E 测试」的条目），确认失败，再补胶水。禁止「先实现等集成时再补测试」。

## 迁移与 schema 任务

先写「查库断言列/索引不存在」的失败测试并跑红，再写迁移，再跑绿；唯一索引与并发约束用集成测试先红后绿（如并发提交同一手机号仅一次成功）。禁止「先写迁移再补查库断言」——迁移先行则断言永不红，约束等于没测过。

## 机检清单（写完逐项勾选，不勾选不得交审）

- [ ] 每条 R（状态「废止」除外）能指向任务编号；缺口已补任务
- [ ] 每个契约的错误情形至少一条失败测试，测试名写在任务卡里
- [ ] 每条可测接缝至少一个任务
- [ ] 每个状态转换至少一个测试任务；每个演示态至少一个 E2E 任务
- [ ] 「不安排任务」清单与 design 非目标逐条一致，无预留任务
- [ ] 任务卡无函数体、无「处理边界情况」「加适当校验」类空话
- [ ] 跨任务名字/类型与前面任务 Produces 完全一致（`clearLayers()` 不得变 `clearFullLayers()`）
- [ ] Review Focus 每行有测试固定在对应任务，条数符合档位
- [ ] Q 条目无验证任务（测试提质阶段验收）
- [ ] 任务卡正文 ≤15 行/张，超限已记裁决

## 执行交接

计划保存并自查后交人工审阅，确认后开始执行。**默认本会话内联执行**：主会话上下文已热，逐任务顺跑 TDD 六步 token 最省、返工最少；上下文隔离靠测试原始输出重定向落 `docs/dev/AXY-<N>-<slug>/evidence/`、只回读汇总行取得，不需要子代理。

**子代理仅两种触发**，并在裁决记录写一行理由：① 存在互不依赖的任务链（Consumes 不相交、文件域不同），并行能实质缩短墙钟；② 单任务探索与输出确实会挤爆主上下文。环境不支持时内联执行并明说，不得假装委派。

**子代理预算四条（HARD-GATE）**：

1. **按链打包，不按任务拆**：同链连续任务合并给一个子代理；禁止一任务一代理，禁止把 TDD 六步拆给多个子代理；
2. **并行链同一条消息派出**；链间有共享文件或 Produces/Consumes 相接的不得并行；
3. **prompt 自包含**：任务卡全文 + Global Constraints + Consumes 的 Interfaces 契约；子代理只定向读任务卡点名文件（带行号范围），不通读 design/tasks；
4. **主会话是裁判**：子代理每任务回传 ≤15 行（红测试名 / 绿通过数 / 全量套件汇总行 / 提交 hash），原始输出落 evidence/，仅失败回传细节；失败打回原子代理续做。

**证据回读四行**：红测试名、绿通过数、全量套件汇总行、提交 hash。其余不进主上下文。

**裁决记录一行**：`裁决: <决定> — <原因> — <代价>`。只进裁决记录节，不改写 design 契约代码块（design 侧留痕至多一行指针）。不写背景故事，不为记而记。

## 合理化对照表

| 借口 | 现实 |
| --- | --- |
| 「计划这么细了，写代码是抄」 | 计划写过了头。签名 + 测试名 + 断言足够，删函数体 |
| 「集成测试等写完一起补」 | 补的测试没红过 = 没测过。集成/E2E 是显式任务，先红后绿 |
| 「这步太简单，合并描述就行」 | 合并后「可检查的结果」就没了。简单就写短，不写含糊 |
| 「执行时遇到再改计划就行」 | 没记录的偏离 = 计划与实现各说各话。裁决入档 |
| 「按 TDD 六步各派一个子代理更可控」 | 拆开的是成本不是风险。六步在同一子代理内闭环 |
| 「每个任务都派子代理，干净又快」 | 每个子代理是一次冷启动。默认内联，输出落盘拿隔离 |
| 「一个一个派稳一点」 | 串行把并行墙钟变成求和。互不依赖的链同一消息并行派出 |
| 「子代理用主模型才放心」 | 质量由任务卡承载，规则 over 模型。实现类用低档模型 |
| 「测试红了我在主会话里修」 | 主会话代跑代修 = 上下文回流爆炸。打回原子代理续做 |
| 「小改动也走全套，保险」 | 档位就是为这设的。轻量档保留门禁与任务卡，砍盘点与 Review Focus |

## 产出物

- `docs/dev/AXY-<N>-<slug>/tasks.md` — 实现计划（含 Tier、Global Constraints、不安排任务、Review Focus、任务卡、机检清单勾选、裁决记录节）
