# 原型契约（prototype-contract）

## 契约的地位

**页面设计分两层：视觉真源是 `studybuddyui/` 布局草稿条目（截图 `result.png` + `prompt.md`），契约是文字接口。** 契约作为 proposal 的一节落盘，承载交互逻辑、状态与边界的唯一事实源；条目承载布局外观与动效规格，契约以条目名引用，不复述条目已呈现的外观。因此：

- 下游（dev_architecture_design、E2E）读契约取交互与状态，看条目截图取布局外观；AI 消费条目一律走截图与 `prompt.md`，**禁止读条目代码**；
- 契约是**演示态清单的唯一源**——没有第二个地方（组件头注释等）维护同一份清单；
- 契约写到**可构建级**：没读过澄清对话的 AI，凭契约 + 条目截图 + 项目公共文档能做出可演示的实现。

体量约束：**契约 ≤ 150 行文本**。引用条目后布局外观不复述，契约应当更瘦；超限不是压缩措辞，而是特性太大——回到用户故事切割判定拆故事（AC ≤ 6，见 product_design 技能）。

## 契约结构

### 1. 演示态清单

| #   | 演示态       | 对应 AC                    |
| --- | ------------ | -------------------------- |
| 1   | <一句话名称> | <AC-N / 演示专态（无 AC）> |

每特性 ≤ 5 个 AC 演示态；AC 取自对应用户故事的验收标准编号。演示专态（如「重置」）允许存在但须显式标注无 AC。**「重置」专态的标准语义**：恢复本特性种子演示数据与全部控件初始值——它是演示辅助而非交付功能，不进验收走查，不要求出现在产品实现中。

### 2. 每演示态一节（可构建级的最小内容）

每态按以下骨架写，缺一项即不可构建：

- **入口**：从哪个页面/状态、什么操作进入本态（页面级跳转引用 proposal 路由行为表的行号）；
- **布局条目**：`studybuddyui/layouts/<条目名>`（视觉真源，含块级布局与动效规格）；无条目时写「豁免 · 文字定义」并登记「开放问题」；
- **布局块清单**：自上而下/自左而右列出界面块（导航、列表、卡片、操作条…），每块一句话说明，字段旁标注 F 编号；块级比例与编排以条目为准，契约只写条目呈现不了的行为（动态显隐、滚动加载等）；
- **视觉 / 交互状态**：不可从 R 推导的 UI 细节（提交中置灰、错误高亮位置、提示消除时机等）；
- **空态与边界态**：无数据、加载、异常时的呈现；
- **关联 R**：本态交互逻辑覆盖的需求编号列表。

**交互逻辑回引，不复述**：验收标准、校验规则、错误文案一律由 R / F / E 表承载，契约只写编号引用——在契约里重写验收文案即制造第二个事实源。

### 3. 布局条目引用与缺口处理

- **有条目**：契约引用条目名；动效规格取条目 `prompt.md` 中 motion-design 的产出，契约不自行发明动画规格；
- **无条目**：向提出者确认后在流程内调用 layout-wireframe（有参考截图/URL）或 layout-blank（一句话页面用途）产出条目——方案选定、审阅归档等人工门由草稿技能承载，本流程不代走；条目归档后回本流程写引用；
- **豁免**：布局无争议的纯流程页，经提出者确认可豁免条目，契约文字定义并在「开放问题」登记豁免；
- **看效果**：有条目看条目截图（`result.png`）；无条目时按契约现场生成一次性 HTML，看完即弃。

**批准门即页面设计基线**：提请批准时，契约引用的布局条目截图随 proposal 一并呈审；批准即锁定页面设计基线——其后的条目增删改走对应草稿技能（layout-upgrade / layout-remove / layout-wireframe），已批准 proposal 的引用按修订规则同步。

### 4. 无演示态交互的归属

有 AC 但不设独立演示态的交互不得「不设演示态」一笔带过——那是不可走查区域。归属规则：页面级行为（守卫、跳转、视图切换）进 proposal 的路由行为表；控件级行为（拖拽、滚动加载、键盘操作等）进需求条目，逐条写明触发动作 → 可观察结果。两处都没有的交互即无走查方式，验收矩阵不得放行。

### 5. 双向贯通规则（无未覆盖区域）

- 每条 AC 必须有走查方式：演示态 N、路由行为 #N 或对应 R 条目——由 proposal 验收矩阵承载双向覆盖核对；
- 每个 AC 演示态必须挂 ≥ 1 条 AC；
- 界面上每个元素必须属于某个演示态；不属于任何演示态的元素不得出现在界面上（范围排除项只在非目标与边界登记，禁止以占位形式呈现）。
- product_proposal_writing 自查清单验证以上三条无遗漏。

### 6. `[NEW]` 标记

界面字段落不到模型属性（proposal「依赖与影响 · 领域模型」）时，在契约文本该字段旁标注 `[NEW]` 待模型支持，并登记 proposal「开放问题」。不得静默略过，也不得为整洁删除标记。
