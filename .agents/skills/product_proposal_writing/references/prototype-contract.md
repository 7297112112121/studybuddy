# 原型契约（prototype-contract）

## 契约的地位

**页面设计分两层：契约是文字接口，视觉真源是 `studybuddyui/` 布局草稿条目——但条目在开发侧 design 期才经布局轮确认产出，proposal 阶段只有契约文字。** 契约作为 proposal 的一节落盘，承载交互逻辑、状态与边界的唯一事实源，并以逐态布局块清单承载布局意图（供 design 布局轮筛选条目）。因此：

- proposal 阶段 AI 只凭契约与项目公共文档工作；条目在 design 期产出后，下游（dev_architecture_design、E2E）看条目截图取布局外观，AI 消费条目一律走截图与 `prompt.md`，**禁止读条目代码**；
- 契约是**演示态清单的唯一源**——没有第二个地方（组件头注释等）维护同一份清单；
- 契约写到**可构建级**：没读过澄清对话的 AI，凭契约 + 项目公共文档能做出可演示的实现（布局外观的确认在 design 布局轮补齐）。

体量约束：**契约 ≤ 150 行文本**。引用条目后布局外观不复述，契约应当更瘦；超限不是压缩措辞，而是特性太大——回到用户故事切割判定拆故事（AC ≤ 6，见 product_design 技能）。

## 契约结构

### 1. 演示态清单

| #   | 演示态       | 对应 AC                    |
| --- | ------------ | -------------------------- |
| 1   | <一句话名称> | <AC-N / 演示专态（无 AC）> |

每特性 ≤ 5 个 AC 演示态；AC 取自对应用户故事的验收标准编号。演示专态（如「重置」）允许存在但须显式标注无 AC。**「重置」专态的标准语义**：恢复本特性种子演示数据与全部控件初始值——它是演示辅助而非交付功能，不进验收走查，不要求出现在产品实现中。

### 2. 每演示态一节（可构建级的最小内容）

每态按以下骨架写，缺一项即不可构建：

- **入口**：从哪个页面/状态、什么操作进入本态（页面级跳转引用 proposal 路由行为表的行号）；
- **布局块清单**：自上而下/自左而右列出界面块（导航、列表、卡片、操作条…），每块一句话说明，字段旁标注 F 编号——写到块级可辨认（每块的形态、相对位置、占比关系），这是 design 布局轮筛选/新建布局条目的依据；动态显隐、滚动加载等条目呈现不了的行为在此一并写明；
- **视觉 / 交互状态**：不可从 R 推导的 UI 细节（提交中置灰、错误高亮位置、提示消除时机等）；
- **空态与边界态**：无数据、加载、异常时的呈现；
- **关联 R**：本态交互逻辑覆盖的需求编号列表。

**交互逻辑回引，不复述**：验收标准、校验规则、错误文案一律由 R / F / E 表承载，契约只写编号引用——在契约里重写验收文案即制造第二个事实源。

### 3. 布局条目的产出时机（design 期）

proposal 期**不产出布局条目**：契约的布局块清单是文字意图，供开发侧 dev_architecture_design 的布局轮筛选——既有条目适配则引用条目名，无适配条目则经 layout-draft 新建，有候选则呈报开发者选择，全部处置经开发者确认后才落 design。动效规格由 design 期条目的 motion-design 产出承载，契约只标记动效意图，不自行发明动画规格。

**批准门锁定交互基线**：提请 proposal 批准时，布局块清单（或按契约现场生成的一次性 HTML，看完即弃）随 proposal 一并呈审，批准即锁定演示态与交互基线；布局视觉基线在 design 批准门锁定（布局条目截图随 design 呈审）——其后的条目增删改走对应草稿技能（layout-upgrade / layout-remove / layout-draft），已批准 proposal 的引用按修订规则同步。

### 4. 无演示态交互的归属

有 AC 但不设独立演示态的交互不得「不设演示态」一笔带过——那是不可走查区域。归属规则：页面级行为（守卫、跳转、视图切换）进 proposal 的路由行为表；控件级行为（拖拽、滚动加载、键盘操作等）进需求条目，逐条写明触发动作 → 可观察结果。两处都没有的交互即无走查方式，验收矩阵不得放行。

### 5. 双向贯通规则（无未覆盖区域）

- 每条 AC 必须有走查方式：演示态 N、路由行为 #N 或对应 R 条目——由 proposal 验收矩阵承载双向覆盖核对；
- 每个 AC 演示态必须挂 ≥ 1 条 AC；
- 界面上每个元素必须属于某个演示态；不属于任何演示态的元素不得出现在界面上（范围排除项只在非目标与边界登记，禁止以占位形式呈现）。
- product_proposal_writing 自查清单验证以上三条无遗漏。

### 6. `[NEW]` 标记

界面字段落不到模型属性（proposal「依赖与影响 · 领域模型」）时，在契约文本该字段旁标注 `[NEW]` 待模型支持，并登记 proposal「开放问题」。不得静默略过，也不得为整洁删除标记。
