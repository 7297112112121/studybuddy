# 前端设计规范

组件选型与 token 消费规则——AI 生成 UI 的裁判文档；token 值唯一真源在 `src/app/globals.css`。本文居技能区 `shared/`，为跨技能共享规则（无 Docusaurus 发布）。本文回答写 UI 时「用什么组件、颜色圆角阴影从哪来、何时允许裸 Tailwind」。选型依据见 `docs/dev/adr/` 的 ADR-0004（shadcn/ui）与 ADR-0003（Tailwind CSS 4）；首个样板见 AXY-8 登录页（`src/modules/auth/components/`）。

## 定位与真源

| 内容                       | 真源                                               | 本文角色                                    |
| -------------------------- | -------------------------------------------------- | ------------------------------------------- |
| token 值（颜色/圆角/字体） | `src/app/globals.css`（`:root` + `@theme inline`） | **零 token 值**，只写消费规则（防双源漂移） |
| 组件源码                   | `src/components/ui/`（shadcn CLI 复制进仓库）      | 写选型表与引入流程                          |
| 交互行为门禁               | `AGENTS.md`（研发流程节 UI 门禁句）                | 本文提供门禁细则（验收自查清单）            |
| 组件选型依据               | ADR-0004（Radix + lucide-react）                   | 引用，不复制                                |

## 主题策略

- **全站固定深空暗色主题**（ADR-0027，自 calendar 页试验转正）：`:root` 语义 token 即暗色校准值（ink 深空底 + aqua 主色），无亮色模式；`.dark` 块已随 ADR-0027 移除，不存在「预留结构」。项目主题（配色语义与数值）请参看 `src/app/globals.css`。
- `dark:` 变体走 Tailwind v4 默认的 `prefers-color-scheme` 媒体查询；**不声明** `@custom-variant dark`（class 手动切换需求出现时再按 ADR-0003 开 ADR）。注意：全站固定暗色后，shadcn 组件自带的 `dark:` 微调类仅在暗色 OS 偏好下触发——语义 token 已按暗色校准，视觉可接受。
- 星点背景由根布局 `StarsBackground` 统一挂载，页面不自带背景层（ADR-0027）。

## 组件选型表

先查此表，再写代码。表内场景**禁止手写平行组件**（重复造轮子是视觉漂移的第一来源）。

| 场景                             | 组件                                                                  | 来源                                                  |
| -------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------- |
| 文本/密码/电话输入               | `Input`（+ `Label`）                                                  | `@/components/ui/input`                               |
| 动作按钮（主/次/幽灵/链接/危险） | `Button`（variant: default / outline / ghost / link / destructive）   | `@/components/ui/button`                              |
| 表单字段标签                     | `Label`                                                               | `@/components/ui/label`                               |
| 页面级错误横幅                   | `Alert`（variant: default / destructive）                             | `@/components/ui/alert`                               |
| 视图/页签切换                    | `Tabs`（Radix，受控 value/onValueChange）                             | `@/components/ui/tabs`                                |
| 原生勾选框                       | **原生 `input[type=checkbox]` + token 类**（见[表单策略](#表单策略)） | —                                                     |
| 分隔线                           | `Separator`                                                           | `@/components/ui/separator`（按需 `shadcn add` 引入） |

表外场景：先 `npx shadcn@latest add <component>` 引入官方组件，单独成 commit（ADR-0004 纪律），再按上表补充登记；确认 registry 无合适组件才允许手写。

## token 消费规则

- **颜色、圆角、阴影一律语义类**：`bg-background` / `bg-card` / `bg-muted` / `text-foreground` / `text-muted-foreground` / `text-destructive` / `border-border` / `border-input` / `ring-ring` / `rounded-lg` / `shadow-sm` 等。
- **禁止**：hex / oklch 裸值、Tailwind 灰阶色（`slate-*` / `gray-*` / `zinc-*`）、裸红绿黄（`red-*` / `green-*` / `amber-*`）。错误用 `text-destructive`，校验汇总用 warning 系（`--warning`，shadcn 默认集外的补充 token）。
- **允许自由 Tailwind 的范围**：布局骨架（flex / grid / absolute）、间距（gap / p-* / m-* / mt-1）、尺寸（w-* / h-* / size-_）、字号字重（text-sm / font-medium）、响应式前缀（md:_）。
- 图标一律 [lucide-react](https://lucide.dev)，禁内联 SVG 手绘。

## 何时允许裸 Tailwind（白名单）

1. 布局骨架与间距排布（上条允许范围）；
2. **原生 checkbox**：测试与 a11y 语义要求 `HTMLInputElement`（Radix Checkbox 渲染 `button[role=checkbox]`），以 token 类（`accent-primary` / `outline-destructive`）样式化；
3. 组件内部合理的定位微调（如密码显隐按钮的 `absolute inset-y-0 right-1`）。

反例（来自改造前的登录页，均为违规）：`bg-slate-100`（→ `bg-muted`）、`text-slate-700`（→ `text-foreground`）、`border-red-500`（→ Input 的 `aria-invalid` 内建描边）、`bg-amber-50 text-amber-800`（→ warning token）、`bg-slate-800` 按钮（→ `Button` default variant）。

## 表单策略

- **默认**：受控组件 + `validators.ts` 纯函数校验 + 状态提升（AXY-8 样板：AuthScreen 持有全部表单态，子组件纯受控）。服务端校验走 zod schema，与客户端校验各司其职。
- **不引入** react-hook-form + shadcn Form：引入等于重写校验架构，现有测试安全网大面积作废。
- 触发信号（出现时再评估 RHF，走 ADR 流程）：单表单字段 > 10、跨步向导表单、需要字段级动态校验规则复用。

## 新增组件引入流程

1. 查[选型表](#组件选型表)——命中则直接 import；
2. 未命中 → `npx shadcn@latest add <component>`（CLI 复制源码进 `src/components/ui/`），**单独成 commit**（ADR-0004）；
3. 更新本文选型表；
4. knip（`npm run lint:unused`）：`src/components/ui/**` 已在 knip entry 声明（库式文件导出免检），不得出现「引入即死代码」的组件——只 add 本期所需。

## 验收自查清单

UI 交付前逐条过（dev_spec_review 终审含 UI 条目时按此抽查）：

1. **错误态**：字段错误有 `aria-invalid` 描边 + 文案；页面级错误有 Alert；校验汇总有 warning 汇总条；
2. **焦点可达**：Tab/Shift-Tab 顺序合理，焦点环可见（shadcn 组件内建 `focus-visible:ring-*`，自写元素须补齐）；
3. **交互完整**：提交中禁用 + 文案切换；空/加载/错误三态至少覆盖错误态；
4. **i18n**：全部文案走 next-intl（`src/locales/zh-CN/`），组件内禁硬编码用户可见文案；
5. **token 违例扫描**：`grep -rn "slate-\|red-[0-9]\|amber-\|#[0-9a-fA-F]\{3,6\}" src/` 无业务代码命中（`src/components/ui/` 上游源码内建 dark: 前缀类除外）；
6. **键盘与语义**：可点元素用 `Button`（不是 div onClick）；表单控件与 `Label` 关联（htmlFor/id）。
