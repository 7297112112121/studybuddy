# 组件升级草稿(component-upgrade)

## 定位

输入为 `studybuddyui/components/` 下一个已存在的组件条目(基底)加一句升级意图,输出为一个新组件条目(副本):复制基底、按选定策略修改副本、归档为新组件。原条目自始至终保持只读——升级永远发生在副本上,这是本技能与直接改组件的本质区别。从零新建走 [component-draft](../component-draft/SKILL.md);页面级布局升级归 layout-upgrade。

产物约定与家族技能一致:`studybuddyui/components/<新组件名>/` 下 `<新组件名>.tsx` + `prompt.md` + `result.png`,目录名即新组件名称。真实组件规范不变:结构、样式、全部交互状态一次给全,全状态陈列,不写死业务文案。

## 硬门禁

1. **策略未选定不动副本**:修改策略只以文字描述呈现,开发者明确选定前禁止创建任何文件(包括副本目录本身)。
2. **原条目只读**:禁止修改基底目录下的任何文件;升级产出只出现在新目录。基底唯一的允许用途是读取其 `<条目名>.tsx` 与 `prompt.md` 作为复制与改写来源——这是本技能的输入,不是违例。
3. **只保存选定策略的修改结果**:副本只创建一个,按开发者选定的那一个策略修改;落选策略的文字描述看完即弃。
4. **审阅未通过不归档**:`result.png` 在开发者确认升级结果无误后才生成;有修改意见则回到修改步迭代,归档动作始终在确认之后。
5. **全状态陈列**:修改后的组件仍须满足默认/Hover/Active/Disabled 四态齐全,扩展态按组件类型推演;新增能力引入的新状态(如新增"加载中"操作)同样要进陈列区。
6. **不碰无关条目**:禁止读取或引用 `layouts/`、`backgrounds/` 及基底之外任何 `components/` 条目的代码;需要了解草稿工作区时读 `README.md`。

## 流程(六步)

### 1. 基底与意图澄清

- 开发者点名基底条目;未点名时列出 `studybuddyui/components/` 下现有条目供其选择。基底不存在时报错呈报,不凭空代建。
- 把升级意图澄清为具体修改点(新增/删除/调整哪些区块与状态、变体变化等);意图含糊(如「优化一下」)时先向开发者澄清,不自行补全。

### 2. 修改策略分析(文字方案)

围绕修改点提出 2-3 个修改策略,以文字列表交开发者挑选。每个策略包含:

- 策略名(如「新增操作以底部固定行承载」);
- ASCII 线框示意图:用方框与缩进画出修改后的区块相对位置与比例,以及新增状态的陈列编排(动了的区块可标注),让开发者在选定前看到大概效果;
- 修改点清单:对区块结构、状态清单、变体的具体影响(哪些区块动、哪些状态新增、哪些不动);
- 取舍理由(为什么这种改法服务升级意图)。

示意图紧随策略名呈现(呈现渠道支持选项预览时放入预览);示意图是对话内的一次性示意,不创建文件(与硬门禁 1 一致)。策略之间应覆盖修改点的实质差异(如「既有区块内扩展」vs「独立新区块承载」vs「替换既有区块」),避免仅间距、尺寸不同的变体。新增区块的规格与新增状态的样式依据 [组件设计方法](../../../docs/dev/组件设计方法.md) 的量化规则(尺寸三档、状态样式公式、阴影分层)。此步禁止创建任何文件。

**动画询问**:升级意图涉及新增交互状态(如加载、成功反馈)时,呈报策略时一并询问开发者是否需要动画设计;选择需要时加载 [motion-design](../motion-design/SKILL.md),为最终选定的策略按其规范产出动画规格,落实到代码过渡与 prompt.md 动画说明;选择不需要则不加进入/退出编排。

### 3. 复制副本

策略选定后:

- 新目录名:根据升级意图建议语义名(如 `event-card-with-cover`),表意不清或拿不准时退回 `<原名>-v2` 递增;名字报开发者确认后使用。
- 完整复制基底的 `<条目名>.tsx` 与 `prompt.md` 到新目录;副本代码文件的 default export 组件名改为与新目录名对应的 PascalCase,不导入工作区内任何其他条目。
- 在 `studybuddyui/src/App.tsx` 的 `DraftKey` 与 `DRAFTS` 中注册新条目,并在 `studybuddyui/` 目录跑 `npx tsc --noEmit`——副本与基底同时可编译预览后,才进入修改步。

### 4. 副本修改

- 按选定策略修改副本的代码文件:沿用基底的结构与视觉规范(色板、圆角、内边距、阴影分层),只改策略涉及的区块与状态。
- 状态陈列区同步更新:新增状态进陈列区并配状态名标注,被删除的状态从陈列区移除;陈列区编排保持「交互演示 → 各状态陈列组」的结构。
- 意图外的区块不做顺手微调;新增或调整的间距按组件设计方法的 8 点栅格取 8 的整数倍。
- 修改完成后按 [组件设计方法](../../../docs/dev/组件设计方法.md) 的组件校验清单自查,通过后再预览。

### 5. 审阅

- 在 `studybuddyui/` 目录启动 `npm run dev`,用 Playwright 打开本地地址并切换到新条目,截图呈报开发者;审阅以升级意图与基底的差异预期为准。
- 开发者确认无误 → 第 6 步;有修改意见 → 回第 4 步修改后重新预览(不重复策略分析)。

### 6. 归档与收尾

- 用 Playwright `browser_take_screenshot` 把组件陈列页截图保存为 `studybuddyui/components/<新组件名>/result.png`:
  - 截图对象为组件草稿容器本身(element 截图),排除草稿工作区顶部的条目切换导航;
  - 页面重新打开后草稿选择复位到第一个条目,截图前先切换到目标条目;
  - 页面存在持续动画(如加载态 `animate-spin` 旋转图标)时,先用 `browser_evaluate` 向 `<head>` 注入 `*, *::before, *::after { animation-play-state: paused !important; }` 暂停全部动画,再执行截图。
- 改写 `prompt.md`:以基底的 `prompt.md` 为底稿,按升级后的区块清单、状态清单与规格修订【设计规格】;直接描述组件设计,禁止「复现 XX 截图」类字样;禁止把 TSX 代码抄进 prompt.md。
- 关闭 dev server,向开发者报告产物路径清单与基底条目的未变性(基底目录无改动)。

## 产出一览

`studybuddyui/components/<新组件名>/` 下三个文件,外加 App.tsx 注册;基底条目保持原样;产物与工作流步骤一一对应:

| 文件           | 内容                                       | 产出时机          |
| -------------- | ------------------------------------------ | ----------------- |
| `<新组件名>.tsx` | 升级后的组件草稿(真实效果 + 全状态陈列) | 第 3-4 步         |
| `result.png`   | 审阅通过后的组件陈列截图                   | 第 6 步审阅通过后 |
| `prompt.md`    | 升级后组件的设计提示词                     | 第 6 步审阅通过后 |

## 合理化对照表

| 借口                                      | 裁决                                                     |
| ----------------------------------------- | -------------------------------------------------------- |
| 就改几行,直接在原条目上改最省事          | 原条目只读,升级只发生在副本(硬门禁 2)                   |
| 策略还没选,先把副本复制出来备用           | 策略未选定不动副本,一个文件都不建(硬门禁 1)             |
| 副本叫 `-v2` 就行,不用问                  | 语义名优先,名字须报开发者确认(流程 3)                   |
| 顺手把基底里的小毛病也修了                | 原条目只读(硬门禁 2)                                    |
| 新增的状态直接写在演示里,不进陈列区       | 全状态陈列,新增能力引入的状态同样要陈列(硬门禁 5)       |
| prompt.md 和基底一样,懒得改               | prompt.md 须反映升级后的设计(流程 6)                    |
| 新状态的样式凭感觉配                      | 新增状态样式按组件设计方法的状态样式公式取值(流程 2)    |
