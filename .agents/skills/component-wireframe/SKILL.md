# 组件草稿(component-wireframe)

## 定位

输入为组件截图/图片或网页 URL,输出为草稿工作区(`studybuddyui/`)中一个真实可交互的组件草稿条目。与布局技能的分工:layout-wireframe / layout-blank 产出灰盒布局骨架,本技能产出真实组件效果——结构、样式、全部交互状态一次给全;只做单个组件,页面骨架与多区域编排不归本技能。

草稿工作区的目录约定与 AI 使用约束以 `studybuddyui/README.md` 为准;本技能只新增条目文件并在 `src/App.tsx` 注册,不改其他条目。

## 硬门禁

1. **方案未选定不落盘**:候选组件方案只以文字描述呈现,开发者明确选定前禁止创建任何文件。
2. **只保存选定方案**:落盘内容仅为开发者选中的那一个方案;候选方案的文字描述看完即弃,不进仓库。
3. **审阅未通过不归档**:`result.png` 在开发者确认组件无误后才生成;有修改意见则回到生成步迭代,归档动作始终在确认之后。
4. **全状态陈列**:默认、Hover、Active、Disabled 四态缺一不可;扩展态(聚焦/加载/错误/空数据等)按组件类型推演补齐。只画默认好看的样子视为未完成。
5. **通用组件红线**:不写死业务文案与业务数据,一律用通用占位文案;组件脱离具体业务场景后必须仍独立成立。
6. **不碰其他条目**:禁止读取或引用 `layouts/`、`backgrounds/` 及其他 `components/` 条目的代码;需要了解草稿工作区时读 `README.md`。

## 多组件轮次

- 参考图/页面包含多个可独立成立的组件时,先识别并列出全部组件(名称 + 一句话说明),**询问开发者需要哪些组件**——开发者可以全选、多选、只选一个,也可以补充图内未列的目标;开发者选定后才组成轮次清单,再逐轮执行。
- 轮次清单 = 开发者选定的组件,每个组件一轮;顺序按开发者的指定或截图中的阅读顺序。
- 每轮完整执行下述六步流程,产出一个组件条目;前一轮归档完成后才开下一轮。
- 全部轮次完成才收尾报告;中途停止时已完成轮次的产物保留,未开始的轮次不落盘。
- 单组件输入不拆轮,直接进入流程。

## 流程(每轮六步)

### 1. 输入获取

- 图片:直接读图。
- URL:用 Playwright MCP `browser_navigate` 打开页面,`browser_take_screenshot` 截取目标组件区域,以截图为分析对象。
- 页面打不开(网络/登录墙)时呈报开发者,改为由开发者提供截图;禁止凭 URL 或记忆猜测组件结构。

### 2. 组件分析(文字方案)

识别组件类型与内部结构,提出 2-3 个候选方案,以文字列表交开发者挑选;结构分区、变体枚举与尺寸档位依据 [组件设计方法](../../../docs/dev/组件设计方法.md) 选择,取值用其尺寸三档、圆角与内边距规则。每个方案包含:

- 方案名(如「上下结构:标签 + 输入区 + 底部提示」);
- ASCII 线框示意图:用方框与缩进画出组件内部区块的相对位置与比例,以及状态陈列的编排方式,让开发者在选定前看到大概效果;
- 区块清单与信息层级(哪些区块并列、哪些嵌套,核心元素与辅助元素);
- 变体与状态清单:风格变体、尺寸档位、必选四态 + 按组件类型应补的扩展态;
- 与参考图的对应关系及取舍理由。

示意图紧随方案名呈现(呈现渠道支持选项预览时放入预览);示意图是对话内的一次性示意,不创建文件(与硬门禁 2 一致)。此步禁止生成任何代码。开发者提出候选之外的方案时,按其描述直接进入下一步。

**动画询问**:呈报方案时一并询问开发者是否需要动画设计;选择需要时加载 [motion-design](../motion-design/SKILL.md),为最终选定的方案按其规范产出动画规格,落实到代码过渡与 prompt.md 动画说明;选择不需要则不加进入/退出编排。

### 3. 生成组件草稿

开发者选定方案后:

- 目录为 `studybuddyui/components/<条目名>/`,条目名即组件名称:kebab-case、概括组件用途(如 `date-picker`);组件名为 PascalCase,代码文件为 `<条目名>.tsx`(如 `date-picker.tsx` 导出 `DatePicker`);名字拿不准时报开发者确认。
- 产出真实组件效果:结构与样式按选定方案与 [组件设计方法](../../../docs/dev/组件设计方法.md) 实现(尺寸三档、圆角规范、内边距规则、状态样式公式、阴影分层);不写死业务文案,用通用占位文案(硬门禁 5)。
- 全状态陈列:页面内并排陈列全部状态,每组配状态名文字标注;Hover/Active 等瞬态在陈列区以静态样式呈现对应视觉,同时用 `hover:`/`active:` 等伪类实现真实交互;禁用/加载/错误/空态按对应规则直接渲染。
- 组件 default export、自包含,不导入工作区内任何其他条目;样式只用 Tailwind CSS 类,不引入新依赖。

### 4. 注册与类型自检

- 在 `studybuddyui/src/App.tsx` 的 `DraftKey` 与 `DRAFTS` 中注册新条目(标签用中文概括组件名)。
- 在 `studybuddyui/` 目录跑 `npx tsc --noEmit`。
- 按 [组件设计方法](../../../docs/dev/组件设计方法.md) 的组件校验清单自查(状态齐全、规格复用、边界处理、反馈与可访问性),通过后再预览。

### 5. 审阅

- 在 `studybuddyui/` 目录启动 `npm run dev`,用 Playwright 打开本地地址并切换到新条目,截图呈报开发者。
- 开发者确认无误 → 第 6 步;有修改意见 → 回第 3 步修改后重新预览(不重复方案分析)。

### 6. 截图归档与 prompt.md

审阅通过后补齐两个归档产物,顺序先截图后提示词:

- 截图归档 `result.png`:用 Playwright `browser_take_screenshot` 把组件陈列页截图保存为 `studybuddyui/components/<条目名>/result.png`:
  - 截图对象为组件草稿容器本身(element 截图),排除草稿工作区顶部的条目切换导航;
  - 页面重新打开后草稿选择复位到第一个条目,截图前先切换到目标条目;
  - 页面存在持续动画(如加载态 `animate-spin` 旋转图标)时,element 截图会因「等待元素稳定」超时:先用 `browser_evaluate` 向 `<head>` 注入 `*, *::before, *::after { animation-play-state: paused !important; }` 暂停全部动画,再执行截图;
  - 截图需完整覆盖全部陈列区(交互演示、各状态陈列组),陈列区超出视口时用整页截图。
- 撰写 `prompt.md`:参照 `components/create-activity-modal/prompt.md` 的【角色】【任务】【设计规格】【约束】四段结构,内容为该组件的设计提示词——
  - 【角色】【任务】:组件定位与产出要求;
  - 【设计规格】:区块清单、状态清单(每个状态的触发方式与视觉样式)、尺寸/圆角/间距/色值等精确数值、交互说明(触发方式、反馈效果、异常流程、动画时长);
  - 【约束】:禁入事项与边界处理规则。
  - prompt.md 直接描述组件设计,禁止「复现 XX 截图」类字样,不提及来源截图或原页面;禁止把 TSX 代码抄进 prompt.md。
- 关闭 dev server,向开发者报告产物路径清单。

## 产出一览

`studybuddyui/components/<条目名>/` 下三个文件,外加 App.tsx 注册;产物与工作流步骤一一对应:

| 文件             | 内容                       | 产出时机          |
| ---------------- | -------------------------- | ----------------- |
| `<条目名>.tsx`   | 组件草稿(真实效果 + 全状态陈列) | 第 3 步生成后落盘 |
| `result.png`     | 审阅通过后的组件陈列截图   | 第 6 步审阅通过后 |
| `prompt.md`      | 组件设计提示词             | 第 6 步审阅通过后 |

## 合理化对照表

| 借口                                         | 裁决                                                                       |
| -------------------------------------------- | -------------------------------------------------------------------------- |
| 参考图里有三个组件,一口气全部生成再统一审阅   | 按轮循环,一轮一个组件走完整六步,审阅归档后再开下一轮(多组件轮次)           |
| 参考图里只有默认态,照着画就够了              | 全状态陈列(硬门禁 4),缺失状态按组件设计方法推演补齐                        |
| 文案直接抄参考图里的业务文案更省事            | 通用组件红线,用通用占位文案(硬门禁 5)                                     |
| 开发者还没选方案,先把组件写好备用            | 方案未选定不落盘(硬门禁 1)                                                |
| 状态太多,陈列区只放默认态                    | 只画默认好看的样子视为未完成(硬门禁 4)                                    |
| 顺手把别的条目的样式一起调了                  | 不碰其他条目(硬门禁 6)                                                    |
| 截图等全部条目做完再批量补                    | 归档在每次审阅确认后立即完成(硬门禁 3)                                    |
