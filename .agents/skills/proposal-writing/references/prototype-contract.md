# 原型契约（prototype-contract）

## 契约的地位

**原型契约是原型的唯一入库资产与 AI 唯一接口**，作为 proposal 的一节落盘。交互原型不入库，因此：

- 下游（architecture-design、spec-review、E2E）一律只读契约，**不存在可读的原型源码**；
- 契约是**演示态清单的唯一源**——没有第二个地方（组件头注释等）维护同一份清单；
- 契约写到**可构建级**：没读过澄清对话的 AI，凭契约 + 项目公共文档能做出可演示的实现。

体量约束：**契约 ≤ 150 行文本**。超限不是压缩措辞，而是特性太大——回到用户故事切割判定拆故事（AC ≤ 6，见 product-design 技能）。

## 契约结构

### 1. 演示态清单

| # | 演示态 | 对应 AC |
| --- | --- | --- |
| 1 | <一句话名称> | <AC-N / 演示专态（无 AC）> |

每特性 ≤ 5 个 AC 演示态；AC 取自对应用户故事的验收标准编号。演示专态（如「重置」）允许存在但须显式标注无 AC。**「重置」专态的标准语义**：恢复本特性种子演示数据与全部控件初始值——它是演示辅助而非交付功能，不进验收走查，不要求出现在产品实现中。

### 2. 每演示态一节（可构建级的最小内容）

每态按以下骨架写，缺一项即不可构建：

- **入口**：从哪个页面/状态、什么操作进入本态；
- **布局块清单**：自上而下/自左而右列出界面块（导航、列表、卡片、操作条…），每块一句话说明；
- **内容与数据形状**：每块展示哪些字段、什么口径（示例值可给一个，不写整组演示数据）；
- **交互触发 → 状态转移**：本态内每个可操作元素一条，统一句式——**当用户【操作 XX 字段（控件类型）】时，系统【提供候选 / 赋值 / 边界钳位 / 校验拦截 / 状态转移等处理】，以实现【XX 约束 / 提示效果】（AC-N）**。一条交互一句话，多条交互分句写，禁止「A → B;C → D」箭头流水账；导航类处理写「状态转移」去向，约束类写「约束 / 提示效果」；
- **空态与边界态**：无数据、加载、异常时的呈现。

### 3. 交互行为说明

有 AC 但不设独立演示态的交互（拖拽、滚动加载、键盘操作等）在此逐条显式描述：**触发动作 → 可观察结果**。禁止「不设演示态」一笔带过——那是不可走查区域。

### 4. 双向贯通规则（无未覆盖区域）

- 每条 AC 必须标注走查方式：〔走查：演示态 N〕或〔走查：行为说明 N〕——AC 行尾标注由用户故事承载时，proposal 转写须保持对应关系；
- 每个 AC 演示态必须挂 ≥ 1 条 AC；
- 界面上每个元素必须属于某个演示态，或登记为占位（见下）。
- proposal-writing 自查清单验证以上三条无遗漏。

### 5. 占位 = 范围排除项的呈现

占位模块在契约中只写三行：**是什么、为什么本期不做（指向 proposal 非目标或范围排除项）、cost drivers**。**不写演示数据细节**——占位在实现中是惰性标注（如灰色芯片文本），不是做出来的假功能。

### 6. `[NEW]` 标记

界面字段落不到模型属性（proposal「依赖与影响 · 领域模型」）时，在契约文本该字段旁标注 `[NEW]` 待模型支持，并登记 proposal「开放问题」。不得静默略过，也不得为整洁删除标记。
