# 计划执行（implementation）

## 概述

开发技能组第四步：把已批准的实现计划（tasks.md）变成产品代码与测试。本技能只做执行——计划怎么写就怎么实现；任务卡缺口停手回 dev_plan_writing 补卡，不在现场发挥。

**开始时声明**：「我正在使用 dev_implementation 技能执行 <特性名> 的实现计划（档位取自 tasks.md 头部 Tier 行）。」

## 流程前后继

上游：dev_plan_writing（已批准的 tasks.md，本技能唯一输入）。下游：branch-wrapup（实现完工后收束 feat 分支）。生命周期真源见 [README](../README.md)「总流程与分支生命周期」。

## 触发范围

**不触发**：tasks.md 未获人工批准；spike/原型验证、一次性脚本、纯文档或纯配置变更（与 dev_plan_writing 一致）；既有缺陷修复与小步重构（不走流程技能）。

## 硬门禁（HARD-GATE）

1. **无先失败的测试，即无产品代码**：逐任务 TDD 六步闭环（tasks.md「执行纪律」节）；集成 / E2E / 迁移任务是显式任务，先红后绿，禁止「先实现等集成时再补测试」。
2. **「不安排任务」就是范围边界**：清单里的不做；执行期想到的新需求记裁决或回产品侧，不现场实现；任务卡没写的产品行为不擅自补。
3. **偏离必须入档再继续**：实现与任务卡冲突（名字、签名、测试名、顺序）时，先按裁决记录节格式追加一行——`裁决: <决定> — <原因> — <代价>`——再继续执行；禁止静默偏离，禁止改写 design 契约代码块（design 侧至多一行指针）。
4. **编码排版纪律与测试同等地位**：import 排版、注释风格、声明顺序等逐条自查；UI 任务另做验收自查。违例当场修，不带出任务，产出代码以人类直接阅读理解为前提——注释解释业务意图而非复述代码。
5. **全量套件绿才算完成**：实现完成的判定 = 全量测试套件绿 + `npm run lint` 绿；只跑本特性相关文件不算完成。
6. **上下文预算（HARD-GATE）**：原始测试输出重定向落 `docs/dev/AXY-<N>-<slug>/evidence/`，主会话只回读**证据回读四行**：红测试名、绿通过数、全量套件汇总行、提交 hash；其余不进主上下文。

## 流程

### 1. 读输入（交接最小集）

只读 tasks.md：Global Constraints、「不安排任务」、Review Focus、执行链、任务卡、裁决记录节。**不回读 design 与 proposal**——执行信息唯一来源是任务卡；发现任务卡缺口（签名不明、断言缺失）时停手回 dev_plan_writing 补卡，不自行脑补。

### 2. 逐链逐任务执行

- 按「执行链」节推进：单链串行顺跑；多链时互不依赖的链并行；
- 每任务 TDD 六步闭环，证据落 evidence/，主会话只留证据回读四行；
- 任务卡留白处按 Interfaces 契约与 Global Constraints 做合理选择——能做对留白处的合理选择，做不对的是计划已决定的事。

### 3. 子代理纪律（多链并行或上下文隔离时）

- **按链打包，不按任务拆**：同链连续任务合并给一个子代理；禁止一任务一代理，禁止把 TDD 六步拆给多个子代理；
- **链间有共享文件或 Produces/Consumes 相接的不得并行；并行链同一消息派出**；
- **prompt 自包含**：任务卡全文 + Global Constraints + Consumes 的 Interfaces 契约；子代理只定向读任务卡点名文件（带行号范围），不通读 design/tasks；
- **主会话是裁判**：子代理每任务只回传证据回读四行；失败打回原子代理续做，不在主会话代跑代修。环境不支持子代理时内联执行并明说。

### 4. 完成收口

全量套件绿 + lint 绿后向用户呈报：逐任务完成汇总（红测试名 / 绿通过数 / 提交 hash）、裁决记录追加条目、遗留问题。

**收束**：呈报完成后触发 branch-wrapup 技能，把 feat 分支 PR 合并回 master；合并须等用户确认，未表态不得自行合并。

## 合理化对照表

| 借口                                   | 现实                                                            |
| -------------------------------------- | --------------------------------------------------------------- |
| 「计划这么细，写代码是抄，测试顺手补」 | 先红后绿是六步不是装饰。先写实现再补测试 = 按实现写测试，永远绿 |
| 「这行顺便改了更好」                   | 「不安排任务」就是边界。顺手改动记裁决或回产品侧                |
| 「名字差点意思，直接改了」             | 相邻任务靠 Produces/Consumes 的名字对齐。改名先记裁决           |
| 「执行时遇到再改计划就行」             | 没记录的偏离 = 计划与实现各说各话。裁决入档再继续               |
| 「按 TDD 六步各派一个子代理更可控」    | 拆开的是成本不是风险。六步在同一子代理内闭环                    |
| 「每个任务都派子代理，干净又快」       | 每个子代理是一次冷启动。默认内联，输出落盘拿隔离                |
| 「一个一个派稳一点」                   | 串行把并行墙钟变成求和。互不依赖的链同一消息并行派出            |
| 「子代理用主模型才放心」               | 质量由任务卡承载，规则 over 模型。实现类用低档模型              |
| 「测试红了我在主会话里修」             | 主会话代跑代修 = 上下文回流爆炸。打回原子代理续做               |
| 「测试输出贴会话里好讨论」             | 原始输出落 evidence/，主会话只留证据回读四行                    |
| 「单文件测试绿了就算完」               | 全量套件绿才算完成，别的特性可能被你改红                        |
| 「import 怎么排无所谓，编译能过就行」  | 排版纪律与测试同等地位，提交前自查，违例当场修                  |
| 「直接合并吧，流程走完了」             | 合并走 branch-wrapup 且须等用户确认。未表态不得自行合并         |

## 产出物

- 产品代码与测试（逐任务提交，Conventional Commits 中文描述）
- `docs/dev/AXY-<N>-<slug>/evidence/` — 测试原始输出（先红后绿证据）
- `docs/dev/AXY-<N>-<slug>/tasks.md` 裁决记录节 — 执行期偏离追加
