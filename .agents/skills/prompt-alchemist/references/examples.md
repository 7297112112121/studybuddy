# Prompt Alchemist — 示例库

> **版本**：v1.11.1（新增分析框架选择器+篇幅自动压缩）


## 输出格式分级规则

根据任务复杂度调整输出详细程度：

### 简单任务（单一问题、明确需求）
直接输出：
- 🔍 诊断（3-5 行）
- ⚡ 蒸馏成品

### 中等任务（需要结构调整）
输出：
- 🔍 诊断
- 🏗️ 结构重构
- ⚡ 蒸馏成品

### 复杂任务（涉及推理、决策、创意）
输出完整 5 部分：
- 🔍 诊断报告
- 🏗️ 结构重构
- 🧠 思考增强
- ⚡ 蒸馏成品
- 📊 变更说明

## 示例零：简单任务优化（新增）

### 原始提示词
```
翻译成英文
```

### 诊断
- 任务类型：翻译
- 乔哈里象限：第四象限（人知AI不知具体需求）→ 必须补充背景
- 核心问题：无上下文、无风格要求、无质量标准

### 优化后
```xml
<role>专业翻译，擅长中英双语商务与技术文档</role>

<task>将以下中文翻译成英文：</task>

<constraints>
- 风格：商务邮件（正式但不过于生硬）
- 要求：保留原意，避免过度意译
- 专业术语保持一致性

<format>
直接输出英文译文，不需要解释
</format>
```

### 大师印记
- 🧪 Goodside: 简单的结构约束 + 格式要求
- 🎯 李继刚: "商务邮件"精准压缩风格（一个属性锁定语气）
- 📊 Schulhoff: 补充背景（风格+要求）
- 🌊 涂津豪: 适度深度——简单任务不需要复杂的思考引导

## 分析类任务框架选择器（v1.11.0 新增）

> **适用场景**：用户请求「分析XX的市场策略/竞争优势/产品现状」等分析类任务
> **问题**：传统做法是固定使用「四维度框架」，但不同产品类型需要不同分析视角

### 核心原则

当遇到分析类任务时，**先判断产品类型，再选择分析框架**：

| 产品类型 | 核心分析框架 | 适用场景 |
|---------|------------|---------|
| **通用产品**（工具/APP/消费品） | 竞争格局 / 用户画像 / 产品定位 / 增长路径 | 大众市场、流量产品 |
| **平台型产品**（双边市场/社区） | 供给侧 / 需求侧 / 网络效应 / 护城河 | 交易市场、社区平台 |
| **toB产品**（企业服务/SaaS） | 客户决策链 / ROI论证 / 竞品替代成本 | 销售驱动、关系驱动 |
| **技术型产品**（AI/基础设施） | 技术壁垒 / 落地场景 / 商业化路径 | 研发驱动、产品驱动 |

### 示例：通用产品分析框架（默认）

**原始**：「帮我分析这个产品的市场策略」

**蒸馏成品**（自动选择通用框架）：
```xml
<role>市场策略分析师，擅长从竞争格局、用户画像、产品定位、增长路径四个维度解构商业问题</role>

<context>
待分析产品：[请填入产品名称、所属公司、目标市场]

补充信息（可选）：
- 产品的核心差异化是什么？
- 目前处于什么发展阶段？（0到1 / 增长期 / 成熟期）
- 主要竞争对手有哪些？
</context>

<task>
基于以下四个维度，分析该产品的市场策略：

1. 竞争格局：直接竞品与间接竞品有哪些？各自的定位差异？
2. 用户画像：目标用户是谁？核心需求与痛点是什么？
3. 产品定位：该产品在市场中的位置？差异化优势是否成立？
4. 增长路径：获客渠道有哪些？单位经济模型是否健康？

分析时，先从四个维度各给出一个核心判断，再展开论证；每个维度不超过200字。
</task>

<format>
分层输出：
- 每个维度以「维度名（核心判断）：展开分析」格式呈现
- 关键数据/结论加粗
- 最后用1-2句话总结整体市场策略的有效性
- 总字数控制在800字以内
</format>

<constraints>
- 分析需有具体判断，避免"视情况而定"类模糊结论
- 如关键信息缺失，请在对应维度标注「信息不足，需补充：XXX」
</constraints>
```

### 示例：平台型产品分析框架

**原始**：「分析这个交易平台的市场策略」
→ **自动识别为平台型**，切换框架：
```xml
<role>平台型商业分析师，擅长解构双边市场、网络效应和护城河构建</role>

<task>
从以下四个维度分析该平台型产品：

1. 供给侧分析：平台如何吸引和服务供给方（卖家/内容创作者）？
   供给方的核心驱动力是什么？切换成本高吗？
2. 需求侧分析：平台如何获取和留存需求方（买家/用户）？
   需求方的选择成本有多高？
3. 网络效应评估：供需两侧是否存在正向网络效应？
   冷启动如何解决？密度效应何时出现？
4. 护城河分析：平台的竞争壁垒是什么？
   能被新进入者复制吗？监管风险如何？
</task>

<format>
分层输出，每个维度不超过200字；
最后总结：平台整体有效性和可持续性判断（1-2句）
</format>
```

### 示例：toB产品分析框架

**原始**：「分析这个SaaS产品的市场策略」
→ **自动识别为toB产品**，切换框架：
```xml
<role>企业级SaaS商业分析师，擅长B2B销售流程和ROI论证</role>

<task>
从以下四个维度分析该toB产品：

1. 客户决策链分析：谁是买单人（EB）？谁是使用者（UB）？谁是影响者（coach）？
   决策周期有多长？关键决策因素是什么？
2. ROI论证能力：产品能带来哪些可量化的价值？
   回本周期有多长？竞品对比有何优势？
3. 竞品替代成本：客户切换到竞品的成本有多高？
   数据迁移成本？培训成本？业务中断风险？
4. 增长引擎：获客方式是销售驱动还是产品驱动（PLG）？
   CAC/LTV比率如何？获客效率瓶颈在哪里？
</task>

<format>
分层输出，每个维度不超过200字；
最后总结：产品市场策略的有效性和可改进点（1-2句）
</format>
```

### 框架选择判断规则

```
用户提到「平台」「双边」「市场」「交易」「社区」
  → 平台型框架

用户提到「SaaS」「企业」「B2B」「销售」「客户」「合同」
  → toB框架

用户提到「技术」「底层」「基础设施」「API」「芯片」
  → 技术型框架

无法判断时 → 默认通用框架 + context中询问产品类型
```

## 示例一：简单事实问答优化

### 原始提示词
```
告诉我关于量子计算的事情
```

### 诊断
- 任务类型：事实问答
- 乔哈里象限：第二象限（人不知AI知）→ 需提升提问精度
- 核心问题：范围太广、无输出格式、无深度引导

### 优化后
```xml
<role>量子计算领域的资深科普专家，擅长用类比将复杂概念通俗化</role>

<task>从以下四个维度介绍量子计算：</task>
1. 核心原理：用不超过3个日常类比解释量子比特与经典比特的本质区别
2. 关键技术：列出当前3个最主流的量子计算实现路径及其优劣势
3. 应用前景：哪些领域最可能率先实现"量子优势"，为什么
4. 当前瓶颈：距离实用化最大的3个技术障碍

<format>
每个维度200字以内，关键术语加粗，避免泛泛而谈
</format>
```

### 大师印记
- 🧪 Goodside: XML标签分层 + 格式约束
- 🎯 李继刚: 角色压缩包（"科普专家+类比"两个属性锁定风格）
- 📊 Schulhoff: 任务拆解（4个子维度）+ 结构化输出
- 🌊 涂津豪: 深度引导（"避免泛泛而谈"暗示需要深入思考）

## 示例二：创意写作优化

### 原始提示词
```
帮我写一篇关于秋天的散文，要写得美一点
```

### 诊断
- 任务类型：创意写作
- 乔哈里象限：第一象限偏第三象限（人知部分AI知部分）→ 需补充审美方向
- 核心问题："美"太模糊、无风格锚定、无情感方向

### 优化后
```xml
<role>散文作家，笔触介于川端康成的物哀美学与汪曾祺的市井温情之间</role>

<context>写一篇关于秋天的散文</context>

<constraints>
- 不出现"金风送爽""秋高气爽"等陈词
- 以一个具体场景开篇（不概括，只白描）
- 情感走向：从感官沉浸到时间感知的微痛
- 篇幅：800-1200字
</constraints>

<examples>
风格锚定：
"梧桐叶落下来的样子，不是飘，是决绝地翻了一个身。"
——注意：具体、动感、情感暗线
</examples>

<format>纯文本，段落间留呼吸感，不使用小标题</format>
```

### 大师印记
- 🧪 Goodside: XML结构化 + 格式锚定
- 🎯 李继刚: 角色用两位作家名精准压缩风格光谱；示例锚定（few-shots的变体）；"决绝地翻了一个身"是Embedding精准命中的范例
- 📊 Schulhoff: Few-Shot锚定（一个风格示例胜过百句描述）；补充背景（情感方向）
- 🌊 涂津豪: "从感官沉浸到时间感知的微痛"——引导意识流式的审美思考路径

## 示例三：代码生成优化

### 原始提示词
```
用Python写一个爬虫
```

### 诊断
- 任务类型：代码生成
- 乔哈里象限：第四象限（人知AI不知具体需求）→ 必须补充背景和结构
- 核心问题：无目标网站、无功能需求、无异常处理要求、无代码规范

### 优化后
```xml
<role>Python高级工程师，代码风格：类型注解完备、docstring完整、异常处理健壮</role>

<task>用Python编写一个通用网页爬虫，要求：</task>

1. 核心功能
   - 输入：起始URL + 最大爬取深度 + 最大页面数
   - 输出：结构化数据（标题、正文、链接、爬取时间）
   - 支持：BFS策略、robots.txt遵守、请求频率限制

2. 技术栈
   - requests + BeautifulSoup（不使用Scrapy）
   - 使用${PYTHON_VERSION:3.10+}特性

3. 质量要求
   - 每个函数添加类型注解和docstring
   - 自定义异常类处理网络/解析错误
   - 支持断点续爬（进度持久化到JSON）
   - 添加rate limiting（默认1秒间隔）

<format>
完整的单文件Python脚本，包含：
- 导入区域
- 常量/配置区域
- 自定义异常
- 核心类/函数
- main()入口
- 使用示例注释
</format>
```

### 大师印记
- 🧪 Goodside: `${PYTHON_VERSION:3.10+}`变量占位符 + 格式约束精确到代码结构
- 🎯 李继刚: 角色压缩包（三个属性：类型注解、docstring、异常处理锁定代码风格）
- 📊 Schulhoff: 任务拆解（3个层级逐步细化）+ 补充背景
- 🌊 涂津豪: "先理解需求全貌再动手"——通过结构化约束避免模型直接跳入编码

## 示例四：复杂推理决策优化

### 原始提示词
```
我该不该辞职创业？
```

### 诊断
- 任务类型：推理决策
- 乔哈里象限：第三象限（人不知AI不知）→ 需人AI协同探索
- 核心问题：无个人背景、无决策框架、无风险评估、过于开放

### 优化后
```xml
<role>资深职业战略顾问，思维方式：先拆解再整合，偏好框架化思考，对风险高度敏感</role>

<context>
我正在考虑是否辞职创业，需要系统化分析这个决策。
</context>

<task>
请在回答前进行深入的意识流思考——不要急于给建议，先审视这个问题的多个维度：
1. 这不仅仅是"要不要辞职"的问题，底层是"什么样的生活才是我想要的"
2. 思考过程中，质疑每一个看似理所当然的假设
3. 注意人们在做此类决策时常犯的认知偏差（沉没成本、幸存者偏差、过度自信）

分析框架：
1. 诊断层：我为什么想创业？（区分"逃离型"和"奔赴型"动机）
2. 评估层：从5个维度打分（0-10）——财务缓冲、市场验证、能力匹配、心理准备、机会成本
3. 决策层：给出3条不同风险偏好的路径（保守/均衡/激进），每条路径标注关键里程碑和退出条件
4. 反思层：审视以上分析本身可能的盲点

<format>
每个层级独立成段，关键判断加粗，维度打分用表格呈现
</format>

<self-criticism>
完成分析后，审视自己的建议：是否过度偏向安全？是否忽视了创业的非理性价值？
</self-criticism>
```

### 大师印记
- 🧪 Goodside: XML结构 + 格式约束 + `<self-criticism>`标签（结构化自我批评）
- 🌊 涂津豪: 意识流思考引导（"审视问题的多个维度""质疑每个假设"）；自适应深度（复杂任务=深层思考）
- 📊 Schulhoff: 任务拆解（4层分析框架）+ 自我批评技法 + 补充背景（认知偏差提醒）
- 🎯 李继刚: 角色压缩包（"先拆解再整合+框架化+风险敏感"三个属性）；"逃离型vs奔赴型"——精准的二元压缩
