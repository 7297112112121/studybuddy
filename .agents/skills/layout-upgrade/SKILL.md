# 布局升级草稿(layout-upgrade)

## 定位

输入为 `studybuddyui/layouts/` 下一个已存在的布局条目(基底)加一句升级意图,输出为一个新布局条目(副本):复制基底、按选定策略修改副本、归档为新布局。原条目自始至终保持只读——升级永远发生在副本上,这是本技能与直接改布局的本质区别。从零新建走 [layout-draft](../layout-draft/SKILL.md)。

产物约定与家族技能一致:`studybuddyui/layouts/<新布局名>/` 下 `code.tsx` + `prompt.md` + `result.png`,目录名即新布局名称。布局骨架规范不变:纯白背景、灰色盒子(`#D9D9D9`)表示区域、白色文字标注编号与区域名、禁止具体组件。

## 硬门禁

1. **策略未选定不动副本**:修改策略只以文字描述呈现,开发者明确选定前禁止创建任何文件(包括副本目录本身)。
2. **原条目只读**:禁止修改基底目录下的任何文件;升级产出只出现在新目录。基底唯一的允许用途是读取其 `code.tsx` 与 `prompt.md` 作为复制与改写来源——这是本技能的输入,不是违例。
3. **只保存选定策略的修改结果**:副本只创建一个,按开发者选定的那一个策略修改;落选策略的文字描述看完即弃。
4. **审阅未通过不归档**:`result.png` 在开发者确认升级结果无误后才生成;有修改意见则回到修改步迭代,归档动作始终在确认之后。
5. **只做布局**:灰盒内不出现组件、表单、图表等内容;标注文字只有编号与区域名。
6. **不碰无关条目**:禁止读取或引用 `components/`、`backgrounds/` 及基底之外任何 `layouts/` 条目的代码;需要了解草稿工作区时读 `README.md`。

## 流程(六步)

### 1. 基底与意图澄清

- 开发者点名基底条目;未点名时列出 `studybuddyui/layouts/` 下现有条目供其选择。基底不存在时报错呈报,不凭空代建。
- 把升级意图澄清为具体修改点(新增/删除/调整哪些区域、比例变化等);意图含糊(如「优化一下」)时先向开发者澄清,不自行补全。

### 2. 修改策略分析(文字方案)

围绕修改点提出 2-3 个修改策略,以文字列表交开发者挑选。每个策略包含:

- 策略名(如「排行榜作为主区第三段追加」);
- ASCII 线框示意图:用方框与缩进画出修改后的区域相对位置与比例(动了的区域可标注),让开发者在选定前看到大概布局效果;
- 修改点清单:对区域结构、编号、比例的具体影响(哪些区域动、哪些不动);
- 取舍理由(为什么这种改法服务升级意图)。

示意图紧随策略名呈现(呈现渠道支持选项预览时放入预览);示意图是对话内的一次性示意,不创建文件(与硬门禁 1 一致)。策略之间应覆盖修改点的实质差异(如「主区内追加」vs「独立侧栏承载」vs「替换既有区域」),避免仅间距、尺寸不同的变体。新增区域的选位与比例依据 [布局设计方法](../../../docs/dev/布局设计方法.md) 的动线模型与栅格整数比。此步禁止创建任何文件。

**动画询问**:升级意图涉及新增交互区域或状态切换时,呈报策略时一并询问开发者是否需要动画设计;选择需要时加载 [motion-design](../motion-design/SKILL.md),为最终选定的策略按其规范产出动画规格,动画说明写入 prompt.md(灰盒骨架不实现动效);选择不需要则不写动画说明。

### 3. 复制副本

策略选定后:

- 新目录名:根据升级意图建议语义名(如 `achievements-layout-with-leaderboard`),表意不清或拿不准时退回 `<原名>-v2` 递增;名字报开发者确认后使用。
- 完整复制基底的 `code.tsx` 与 `prompt.md` 到新目录;`code.tsx` 的 default export 组件名改为与新目录名对应的 PascalCase,不导入工作区内任何其他条目。
- 在 `studybuddyui/src/App.tsx` 的 `DraftKey` 与 `DRAFTS` 中注册新条目,并在 `studybuddyui/` 目录跑 `npx tsc --noEmit`——副本与基底同时可编译预览后,才进入修改步。

### 4. 副本修改

- 按选定策略修改副本的 `code.tsx`:沿用基底的结构与规范,只改策略涉及的区域;灰盒规范(纯白背景、`#D9D9D9`、白字标注)不变。
- 区域编号按修改后的阅读顺序完整重排(如 `1、分类侧栏`、`2.1、统计横幅`、`2.2、徽章网格区`、`2.3、排行榜区`),不沿用基底编号留空洞或乱序。
- 意图外的区域不做顺手微调;新增或调整的间距按布局设计方法的 8 点栅格取 8 的整数倍。
- 修改完成后按 [布局设计方法](../../../docs/dev/布局设计方法.md) 的布局校验清单自查,通过后再预览。

### 5. 审阅

- 在 `studybuddyui/` 目录启动 `npm run dev`,用 Playwright 打开本地地址并切换到新条目,截图呈报开发者;审阅以升级意图与基底的差异预期为准。
- 开发者确认无误 → 第 6 步;有修改意见 → 回第 4 步修改后重新预览(不重复策略分析)。

### 6. 归档与收尾

- 用 Playwright `browser_take_screenshot` 把布局截图保存为 `studybuddyui/layouts/<新布局名>/result.png`:
  - 截图对象为布局草稿容器本身(element 截图),排除草稿工作区顶部的条目切换导航;
  - 页面重新打开后草稿选择复位到第一个条目,截图前先切换到目标条目。
- 改写 `prompt.md`:以基底的 `prompt.md` 为底稿,按升级后的区域清单、编号与比例修订【设计规格】;直接描述布局设计,禁止「复现 XX 截图」类字样;禁止把 TSX 代码抄进 prompt.md。
- 关闭 dev server,向开发者报告产物路径清单与基底条目的未变性(基底目录无改动)。

## 产出一览

`studybuddyui/layouts/<新布局名>/` 下三个文件,外加 App.tsx 注册;基底条目保持原样:

| 文件         | 内容                                       |
| ------------ | ------------------------------------------ |
| `code.tsx`   | 升级后的布局骨架组件(灰盒 + 标注)         |
| `prompt.md`  | 升级后布局的设计提示词                     |
| `result.png` | 审阅通过后的布局截图                       |

## 合理化对照表

| 借口                                     | 裁决                                                     |
| ---------------------------------------- | -------------------------------------------------------- |
| 就改几行,直接在原条目上改最省事         | 原条目只读,升级只发生在副本(硬门禁 2)                   |
| 策略还没选,先把副本复制出来备用         | 策略未选定不动副本,一个文件都不建(硬门禁 1)             |
| 副本叫 `-v2` 就行,不用问                 | 语义名优先,名字须报开发者确认(流程 3)                   |
| 顺手把基底里的小毛病也修了               | 原条目只读(硬门禁 2)                                    |
| prompt.md 和基底一样,懒得改             | prompt.md 须反映升级后的设计(流程 6)                    |
| 灰盒里放个真排行榜组件,效果更直观       | 只做布局,标注文字只有编号与区域名(硬门禁 5)             |
| 新区域编号接着旧的写,重排太麻烦         | 编号按修改后阅读顺序完整重排(流程 4)                    |
