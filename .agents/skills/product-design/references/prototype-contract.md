# 原型契约与一次性原型（prototype-contract）

## 契约的地位

**原型契约是原型的唯一入库资产与 AI 唯一接口。** 交互原型不入库（硬门禁 2），因此：

- 下游（proposal-writing、spec-review、E2E）一律只读契约，**不存在可读的原型源码**；
- 契约是**演示态清单的唯一源**——没有第二个地方（组件头注释等）维护同一份清单；
- 契约写到**可构建级**：没读过澄清对话的 AI，凭契约 + 项目公共文档能做出可演示的实现。Builder Check 是这条标准的验收。

体量约束：**契约 ≤ 150 行文本**。超限不是压缩措辞，而是故事太大——回到 MVP 切割拆故事。

## 契约结构

### 1. 演示态清单

| # | 演示态 | 对应 AC |
| --- | --- | --- |
| 1 | <一句话名称> | <AC-N / 演示专态（无 AC）> |

每故事 ≤ 5 个 AC 演示态。演示专态（如「重置」）允许存在但须显式标注无 AC。**「重置」专态的标准语义**：恢复本故事种子演示数据与全部控件初始值——它是演示辅助而非交付功能，不进验收走查，不要求出现在产品实现中。

### 2. 每演示态一节（可构建级的最小内容）

每态按以下骨架写，缺一项即不可构建：

- **入口**：从哪个页面/状态、什么操作进入本态；
- **布局块清单**：自上而下/自左而右列出界面块（导航、列表、卡片、操作条…），每块一句话说明；
- **内容与数据形状**：每块展示哪些字段、什么口径（示例值可给一个，不写整组演示数据）；
- **交互触发 → 状态转移**：本态内每个可操作元素，点了之后发生什么、转到哪个态或给出什么反馈；
- **空态与边界态**：无数据、加载、异常时的呈现。

### 3. 交互行为说明

有 AC 但不设独立演示态的交互（拖拽、滚动加载、键盘操作等）在此逐条显式描述：**触发动作 → 可观察结果**。禁止「不设演示态」一笔带过——那是不可走查区域。

### 4. 双向贯通规则（无未覆盖区域）

- 每条 AC 必须标注走查方式：〔走查：演示态 N〕或〔走查：行为说明 N〕；
- 每个 AC 演示态必须挂 ≥ 1 条 AC；
- 界面上每个元素必须属于某个演示态，或登记为占位（见下）。
- Builder Check 验证以上三条无遗漏。

### 5. 占位 = 三桶的 ❌

占位模块在契约中只写三行：**是什么、为什么尚无故事（指向三桶 ❌ 行）、cost drivers**。**不写演示数据细节**——占位在实现中是惰性标注（如灰色芯片文本），不是做出来的假功能。

### 6. `[NEW]` 标记

界面字段落不到模型属性时，在契约文本该字段旁标注 `[NEW] 待模型支持`，并登记「开放问题」。不得静默略过，也不得为整洁删除标记。

## spike 一次性原型

用途：争议交互、说不清的体验、探索型需求。属性：**易耗品，不是资产**。

| 规则 | 内容 |
| --- | --- |
| 形态 | 单文件 HTML，双击即开，无构建、无本地依赖（可用 CDN）；原生或 React(babel-standalone) 皆可 |
| 必含 | 至少一个非 happy-path 态（空态 / 失败态）——只有顺利路径的原型是在为缺失的状态背书 |
| 位置 | 本地临时目录（如系统临时目录），**不提交、不入库** |
| 生命周期 | 看完即弃；有价值的结论回灌故事文档（契约 / 开放问题）；**产物转正 = 新请求，重新过批准门** |
| 时机 | just-in-time：只在提出者需要看、或交互争议无法用文字收敛时做；不预先生成；被拒后不再提 |
| 自查 | 交付给提出者看之前自查明暗两色、窄屏可用；低保真即可，重点是状态与交互可操作 |
