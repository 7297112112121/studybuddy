# 文档编写(doc_writing)

## 触发范围

**适用**:仓库内一切 `.md` 文件的编写与修改。`.md` 在 Docusaurus 一律按 MDX 编译,编译纪律对所有文档同效。

**不适用**:一次性产物(交互原型 HTML、临时说明)、代码内注释(真源在 docs/dev/编码排版纪律.md)、流程工件的内容结构(由 product_design 等流程技能承载)。写流程工件正文时,本技能的行文纪律仍然适用。

## 硬门禁

1. **规则文档只写规则**。基线规则文档的正文只能是规则条目与其执行示例,每段示例对应一条规则。禁止出处叙事(「规则来自 X」「以 Y 为榜样」「参考 Z 的做法」);禁止背景铺垫;禁止「为什么这么定」的论证节。
2. **不搬运其他文件**。禁止复述、抄写、摘要其他文件的正文进当前文档;跨文件指向一律用相对链接,链接文字只说位置,不转述内容。例外:代码示例中的符号名;流程技能交接最小集声明的输入。
3. **禁止文字堆砌**。每句话承载新信息;删掉后含义不变的句子一律删除。同义重复、复述刚写完的内容、装饰性强调(「务必」「牢记」)、凑段落的过渡句,全部禁止。
4. **规则修改 = 完整替换**。改规则时直接写出新条目,旧条目删除;禁止「不再……而是……」「不是……,是……」等转折与对比;禁止变更说明、废弃标记等留痕。改完的文档读起来与规则从未变过一致;变更历史归 git,不归文档。
5. **交付前过自查表**。逐项勾选,未全勾不得交付。

## MDX 编译纪律

- 行内代码包住一切含 `{`、`<`、`>` 的片段;段落不以 `import` 开头;
- 站内链接用相对路径;
- `docs/` 内改动,提交前 `cd website && npm run build` 验证(门禁 `onBrokenLinks: 'throw'`)。

## 自查表

- [ ] 基线规则文档无出处叙事、无榜样背书、无论证节,正文只有规则与示例
- [ ] 无搬运其他文件内容;跨文件指向全是相对链接,链接文字不转述
- [ ] 逐句检查:删后含义不变的句子已删
- [ ] 无「不再/不是……而是/是」转折、无变更说明、无废弃标记
- [ ] 改动条目读起来像首次写就
- [ ] 含 `{}`/`<>` 片段已包行内代码;无段落以 `import` 开头
- [ ] 站内链接为相对路径
- [ ] `cd website && npm run build` 通过(docs/ 内改动时)

## 合理化对照表

| 借口                         | 现实                                   |
| ---------------------------- | -------------------------------------- |
| 「写明出处显得有依据」       | 依据在链接目标与 git 历史里,不在正文里 |
| 「把上游文件抄来读者更方便」 | 抄本会漂移,链接不会                    |
| 「多强调几句更保险」         | 强调不产生信息,重复即堆砌              |
| 「旧规则留个说明方便对照」   | 两套规则并存,读者无从判断哪条有效      |
| 「就一条小修改,不走自查表」  | 留痕和转折语恰恰最容易出现在小修改里   |
