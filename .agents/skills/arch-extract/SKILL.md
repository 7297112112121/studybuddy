# 架构小步抽取(arch-extract)

## 定位

**轻量工程操作技能**:横切于研发流程之外,任意阶段可对既有代码触发。只负责「把一个类里的工具方法 / 业务编排 / 私有方法群抽成独立文件或函数」这一段局部结构优化(对象不限于类:UI 屏组件树的展示块拆分、状态逻辑 hook 化同属此列)。**规则真源收敛**(识别并拆除规则字面值的跨文件复写与第二份运行时实现,把规则收进单一属主文件)同属本技能管辖:它改变的是规则的落点与引用方式,不是外部行为,不属于被禁的语义重构。不做特性架构设计(归 dev_architecture_design)、不做性能优化、不做语义重构。抽取前后外部行为必须完全不变。

**开始时声明**:「我正在使用 arch-extract 技能分析 `<目标文件/类>`。」

## 硬门禁(HARD-GATE)

1. **用户未拍板,不得改任何产品代码**:每轮只产出建议清单,明确等待用户逐条批准 / 否决 / 追问;用户否决的建议记录原因后不得在本会话再次提出,除非用户主动翻案。
2. **单轮落地范围上限**:一次落地只做一件事(抽一个方法群到一个文件),涉及文件 ≤ 5 个(含测试的 import 路径更新);超出即拆为多轮。禁止顺手改无关代码、禁止改公共 API 签名、禁止动数据库 schema / 路由结构 / 依赖版本。
3. **行为不变铁律**:抽取前后导出签名与运行时行为不变;既有测试一律不改断言,只允许改 import 路径(唯一例外:测试对模块 barrel 做 `vi.mock` 整体替换时,mock 工厂须同步补入新抽出并经 barrel 导出的真实成员,守卫断言不动)。UI 目标以「渲染产物等价」为判据:建议前拍 Playwright 基线截图,落地后同参数重截对比一致。`npm run test` + `npm run lint` 全绿是每轮落地的完成标准,红了必须回滚本轮改动并呈报。
4. **目录变更须同步文档**:凡在 `src/` 新建/移动文件,落地后立即核对并修订 `docs/dev/代码目录.md`;修订前先问用户是否接受目标位置。
5. **测试是安全网不是橡皮筋**:目标代码已有测试覆盖才可抽取;无覆盖时先向用户呈报风险,由用户决定「先补测试再抽」还是「放弃此条」。
6. **与 ADR 冲突即停**:抽取位置或手法与既有 ADR(docs/dev/adr/)冲突或无覆盖时,停下走 ADR 流程,不得先斩后奏。
7. **历史文档不阻碍进行中的工作**:已完成开发的用户故事(story/proposal/design/tasks/review 等工件)归属历史文档,只负责留痕,不阻碍正在进行的工作;抽取与其记载冲突时不构成停下理由,落地汇报中如实记录差异即可。ADR 仍按门禁 6 处理,不在此列。

## 流程(每轮五步)

### 1. 侦察

优先用 codegraph(`codegraph_explore` 报目标类名)一次拿到:类全貌、各方法源码、调用方、影响面(是否有测试)。禁止盲 grep 重读 codegraph 已返回的文件。

UI 屏/组件目标加两条:1. 先 Playwright 拍现状基线截图并画出**现状组件树**(谁渲染谁、状态收在哪),作为「渲染产物等价」验收锚点;2. 搬类型/文件前先 grep 测试与全部调用方的 import 面——测试只锚 DOM 或默认导出时类型可零改动搬家,类型有外部消费者则逐个列入影响面。

### 2. 建议清单(本轮唯一产出物)

每条建议固定五字段,缺一不发:

| 字段       | 要求                                                                |
| ---------- | ------------------------------------------------------------------- |
| 抽什么     | 方法名 + 一句定性(工具方法 / 业务编排 / 私有方法群)                 |
| 抽到哪     | 具体目标路径(遵循 `docs/dev/代码目录.md` 约定),新建文件给出建议命名 |
| 理由       | 架构师视角:内聚性 / 复用 / 可测性,2-3 句,不许空话                   |
| 影响面     | 调用方清单、需更新的 import、测试是否受影响                         |
| 风险与回滚 | 一句风险 + 回滚方式(如「单提交,git revert 即回」)                   |

清单按建议优先级排序;整轮无值得抽的内容时诚实说「该类结构已足够内聚」,不硬凑建议。

**归属判断基准**(「抽到哪」的说理锚点,依次核对):1. 路由组级共享视觉 → 路由组 layout;2. 与生产者同源的词汇类型 → 生产者文件(校验返回键 → validators、错误映射键 → errors);3. 屏级/域级状态机 → 模块根扁平 hook 文件(`use*.ts`,不开 `hooks/` 目录);4. 有真实分支的内联 JSX → 显式 props 契约的小组件。提出每条建议时须同步说出**结构连锁**(如宣传列迁 layout ⇒ grid 容器同迁 ⇒ `<main>` 上收),连锁在规划阶段摆明,不落地时才发现。

**真源收敛判据**(建议清单的常备扫描项,命中即出建议;用户裁决「实现一次改动无歧义」为真源收敛的目标形态,auth 校验域 validators.ts 收敛为先例):

1. **独立字面值从真源人工抄写**(正则量词抄出的长度常量、插件配置里手抄的界限、文案里的数字):平时与真源一致,改真源时静默失真;最隐蔽也最优先拆除;
2. **同一规则存在两份运行时实现**(客户端校验函数 + 服务端第二实现及其错误映射):先问能不能是同构纯函数让客户端与服务端共用一份,能则第二实现整体拆除,不能才考虑收敛到常量级同源;
3. **不能引用常量的载体(JSON 文案)**:用 i18n ICU 插值衔接常量,插值参数在渲染入口统一注入;确实无法衔接的,加一致性测试锁定字面值与常量的绑定;
4. **「唯一豁免」类条款是收敛空间信号**(如依赖方向的「唯一反向豁免」):遇到时先问该豁免服务于什么,向用户提出「放宽为规则 + 同步 docs/dev/代码目录.md」的方案,不默认维持;
5. **收敛落点**遵循归属判断基准第 2 条:域内规则收属主文件(校验域 → validators),配置消费方一律改引真源、禁止复写字面值;真源测试补两类守护:常量与产品字面值的绑定测试、消费方引用真源的断言(防回退成复写)。

**收敛落地与硬门禁 3 的关系**:行为不变铁律约束外部可观察行为(文案渲染产物逐字符不变仍是验收线);收敛类落地允许两类测试改动,须在建议清单影响面逐条列明、经用户批准——1. 断言对象已随规则迁移的守护测试同步迁移(如 i18n 字面值断言改占位符模板);2. 断言被拆除第二实现的用例删除,前提是等价断言已在真源测试全覆盖。其余断言仍不动。

清单末尾固定附**本轮不抽清单**:显式列出不动什么与为什么不(如叶子组件保持既有 props 契约、不引入注入对象)。「禁止堆积」是双向约束——组合层的既有职责(如父子 props 接线)不视为堆积,一刀切清空同样违规。

### 3. 等待决策

显式收尾:「请逐条批准 / 否决 / 追问,或指示下一轮方向。」用户拍板前不进入第 4 步。

### 4. 落地(仅限被批准的条目)

小步执行:移动方法 → 更新 import → `npm run lint` → `npm run test`。红了回滚本轮并呈报(硬门禁 3)。目录变化同步第 5 步。新建/迁移的代码按 `.agents/skills/shared/编码排版纪律.md` 执行(被改文件的新写注释去编号标记重写,存量注释不追溯);落地执行批准清单预判的结构连锁,执行中发现清单外的新连锁时停下重新征求,不得先斩后奏。

### 5. 验证与收轮

汇报 diff 摘要 + 测试结果;UI 目标重截基线截图逐张对比一致后才能收轮。必要时修订 `docs/dev/代码目录.md`。然后回到第 1 步进入下一轮,或用户宣布收尾。

## 多轮循环约定

- 一轮 = 建议 → 决策 → 落地 → 验证。任意一步用户可叫停或改向。
- 用户「全部批准」视为逐条批准,仍按硬门禁 2 的范围上限分轮落地。
- 跨轮记忆:已否决条目 + 已落地条目在每轮建议清单开头用两行简报,防止重复建议与上下文膨胀。
