## 用户故事、proposal 与一次性原型

- 编号体系：登记与工件目录统一用特性编号 `AXY-<N>`，**编号由项目管理平台生成，技能与 AI 不得自行分配、顺延或复用**（历史线框组件编号 `Us<N>` 已随组件退役）。
- 定位入口：编号即路径——`AXY-<N>` 对应 `docs/product/AXY-<N>-<slug>/`（故事 `story.md` + 需求规范 `proposal.md`），index.md 仅总览仪表盘，禁止按文件名盲搜。
- 分工：用户故事只装五大组成部分（故事陈述、验收标准、故事点、优先级、完成定义），一页纸以内；范围、非目标、领域建模等规范内容由 proposal 承接。
- 交互原型一律不入库：proposal 的「原型契约」节是原型的唯一资产与 AI 唯一接口（演示态清单唯一源）；需要看效果时按契约现场生成一次性 HTML，看完即弃（规范见 proposal-writing 技能 `references/prototype-contract.md`）。

## 特性开发工件

```
docs/product/AXY-<N>-<slug>/
├── story.md       # 用户故事（product-design；五大组成部分，编号未下发时平铺、回填时迁入并建目录）
└── proposal.md    # 需求规范（proposal-writing；批准门一：草案 → 已批准；含原型契约）

docs/dev/AXY-<N>-<slug>/
├── design.md      # 架构设计（architecture-design；批准门二：草案 → 已批准；落盘时建目录）
├── tasks.md       # 实现计划（plan-writing）
└── review.md      # 审查报告（spec-review；性能与质量要求移交测试提质）
```

一个特性一对同名目录，product 侧 `{story, proposal}` 与 dev 侧 `{design, tasks, review}` 镜像对应，编号与 slug 沿用对应用户故事。

## AI 技能文档

`.agents/skills/`（仓库路径，经 symlink 挂到各工具目录，不进文档站）：

- `README.md` — 技能清单唯一真源与「流程接力约定」（下游技能默认只读的交接最小集）；
- 流程技能五个：product-design / proposal-writing / architecture-design / plan-writing / spec-review，各含 `SKILL.md`（只做路由、门禁、决策）与 `templates/`；
- 外部技能以 `skills-lock.json` 锁定安装，不得手改。

## AI 纯文本端点

文档站构建时由 `website/src/plugins/ai-docs/` 自动生成面向 AI 的纯文本端点：

- `llms.txt` — 全站索引（分节对齐 `docs/` 一级目录），入口 `https://7297112112121.github.io/studybuddy/llms.txt`；
- `llms-full.txt` — 全量打包，便于一次性载入上下文；
- 每页 `.md` 端点 — 任一文档页 URL 加 `.md` 后缀即纯文本版。

格式约定：给 AI 的指令与规范一律 `.md`，面向人类的富媒体页一律 `.mdx`。
