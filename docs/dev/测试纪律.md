# 测试纪律

涵盖测试分层 mock 边界、mock 目标校验、测试寻址、测试共享件唯一实现与统一接口端点壳纪律——凡编写或修改测试与统一接口路由的技能在每任务提交前逐条自查的裁判文档。本文件是测试纪律的真源,规则**包括但不局限于**以下条目,新增测试纪律登记于此。

## 分层 mock 边界

- 每层测试只 mock 被测层真实依赖的相邻下一层:组件测试 mock store(useCalendarStore.getState 形状)与 next/navigation,链测试 mock store,store 测试经 vi.stubGlobal 桩 fetch,契约切面测试 mock 会话读取与 logger;
- mock 目标必须是被测物 import 图中的真实模块;重构移动层间依赖时,同任务迁移受影响测试的 mock 目标,禁止保留已解散模块词汇的 mock;
- 负断言(未被调)不作为唯一证据:mock 钉在无人 import 的模块上时负断言恒真,绿测不证明接线正确,依赖 mock 目标门禁兜底。

## mock 目标门禁

- vi.mock 的 "@/…" 目标与含 "/src/" 的相对目标必须在 src/ 下真实存在(.ts/.tsx/index.*),裸模块名不校验;校验由 scripts/check-test-mocks.mjs 承担并随 npm run lint 执行,漂移在 lint 期报错。

## 测试寻址

- tests 内引用 src 一律走 @/ 别名(与产品代码同一套解析),禁止相对路径跨入 src,ESLint no-restricted-imports 守增量;vi.mock 目标字符串与 import 寻址同规。

## 测试共享件唯一实现

- 跨轨测试共享件(造号等)落 tests/support/,单实现单出处,单元轨、接口轨与 E2E 轨同源导入,禁止各轨各自实现同规则件;接口轨认证直调基座落 tests/endpoint/helpers.ts;
- 共享件的生成规则以校验层导出成员为锚做符合性测试(如造号产出断言过 USERNAME_RE),规则漂移时符合性测试先红。

## 统一接口端点壳纪律

- route handler 壳只做请求折叠(searchParams/body/params 折成普通对象)与契约切面调用、respondWith 回写,壳内不得堆业务逻辑,新增逻辑先落契约切面或 service;
- HTTP 分发(URL 路由、方法分发、params 注入、Content-Type 处理)回归由 E2E 承接;接口测试直调 handler 不覆盖分发层,属已知空隙非缺陷。
