# 组件划分方法

## 组件划分规则

页面拆成哪些组件、各管什么的裁判规则；dev_architecture_design 设计组件树、dev_implementation 落码两方共用。

- **职责三分类，一文件一职责**：1. 状态机——持状态与校验/提交链，不写排版 JSX；2. 组合层——调 hook、父子接线、条件渲染，自身零状态；3. 纯展示——零状态，内容全来自 props 或静态文案。状态与排版 JSX 混居一个文件是臃肿组件的第一成因，违例。
- **屏组件默认形态**：页面入口组件是组合层；可提取的状态机一律抽为模块根扁平 hook（`use*.ts`，不开 `hooks/` 目录）。
- **内联禁免判据（满足其一不得内联）**：1. 不消费任何状态/回调的静态 JSX——路由组级共享的（如背景层）归路由组 layout，模块私有的（如宣传列）独立纯展示组件；2. 含真实分支逻辑的内联 JSX——独立小组件 + 显式 props 契约；3. 同一交互逻辑（如聚焦浮层开合）在两个组件重复——上提共享。
- **类型词汇同源**：校验返回键归请求契约(<域>-request)、错误映射键归 errors、状态形状跟随持有它的 hook；类型禁与组件文件同居。
- **双向约束**：组合层的父子 props 接线是份内职责，不视为堆积；禁止一刀切清空、禁止为假想复用过早抽象、禁止以注入对象替代叶子组件的 flat props 契约。
- **规模信号**：单组件文件超约 150 行即视为划分违约，回设计重新划分。
