# 代码目录

本文用图呈现 `src/` 的目录树、路由、业务切片与数据流向。

> 数据流注重构裁决见 [架构评审：数据流向统一与增删改查收敛](arch-review/data-flow-unification.md)；代码迁移随 feat 流程落地，本图为落地后的目标形状。

## 目录树

```
studybuddy/
├─ src/
│  ├─ app/                      # 路由层：薄壳（页面客户端化组装 + 统一接口端点）
│  │  ├─ (auth)/                # 登录/注册布局组（不影响 URL）
│  │  ├─ (app)/                 # 主应用布局组（客户端会话守卫）
│  │  └─ api/                   # 统一接口：contract 契约切面 + 自写 route.ts + Better Auth 托管端点
│  ├─ features/                 # 业务组件：各业务域 UI，只订阅 store（内部结构见「业务切片」）
│  │  └─ <m>/
│  ├─ modules/                  # 业务逻辑：queries/service/validators
│  │  └─ <m>/
│  ├─ auth/                     # 认证：Better Auth 服务端实例
│  ├─ db/                       # 各域 schema（含 auth-schema）+ barrel、migrations/
│  ├─ common/                   # 无业务语义全局共享件：date、routes、redis
│  ├─ components/               # 纯展示基础件
│  │  ├─ ui/                    # shadcn/ui 基础组件
│  │  └─ <通用组件>.tsx          # 无业务语义的通用展示组件
│  ├─ stores/                   # 客户端持有层：zustand 业务切片 + Better Auth 会话（authClient）
│  ├─ i18n/                     # next-intl 请求配置
│  └─ locales/                  # i18n 文案（zh-CN）
├─ tests/                       # 单元测试，按域分目录
├─ e2e/                         # Playwright 用例
├─ agent-service/               # python 世界：AgentScope 2.0 Agent Service
│  ├─ main.py                   # 入口：组装框架 service（create_app：storage/message bus/workspace）+ 启动
│  ├─ agent/                    # agent 配置组装：model/credential、toolkit、middleware、技能装载
│  ├─ api/                      # 唯一入口（Next→python）：会话事件流端点 + Better Auth 会话映射
│  ├─ memory/                   # mem0 存储适配层（经 adapters 通道转发，不自持记忆逻辑）
│  ├─ tool/                     # FunctionTool 封装：只写工具语义，不发 HTTP
│  ├─ skill/                    # 技能包：运行时可加载能力包，与 tool 分离
│  ├─ mcp/                      # MCP 连接配置：server 清单与 transport 声明
│  ├─ adapters/                 # 唯一出口（python→Next）：内网 API client（mem0 存储、工具数据共用）
│  ├─ pyproject.toml            # python 依赖钉版（2.x minor）
│  ├─ Dockerfile                # python 镜像构建
├─ docs/  website/              # 文档与文档站
└─ Dockerfile  compose.yaml  Caddyfile    # 部署编排：双应用镜像（app + agent-service），同一 compose（ADR-0016/0029）
```

## 路由

```
URL 空间

/ ──按登录态分流──▶ 已登录 → (app) 布局组
│                  未登录 → (auth) 布局组
│
├─ (auth) 布局组
│   └─ <page>/      认证页 ──已登录访问──▶ 重定向回 (app)
│
└─ (app) 布局组
    └─ layout.tsx 客户端守卫：会话 store 判断，未登录 ──▶ redirect 到 (auth)
        └─ <page>/   业务页（薄壳，渲染 features）

API 端点（统一接口，src/app/api/）
/api/<m>/…       自写 CRUD 端点（读 GET / 写 POST）
/api/auth/…      Better Auth 托管认证段 + 自写注册端点
/api/<chat>      AI 段 SSE 端点（BFF 外包 agent-service）
```

## 业务切片

业务域成对切片：features 持有 UI，modules 持有逻辑，同名对应，中间只隔 store 与统一接口。

```
src/features/<m>/
┌─ 业务组件 ───────────────────────────────────────┐
│ components/        业务组件（只订阅 store）        │
│ useClientScreen.ts 客户端交互逻辑                  │
│ date-nav.ts        域内日期数学（客户端消费）       │
└──────────────────────────────────────────────────┘

src/modules/<m>/
┌─ 业务逻辑 ───────────────────────────────────────┐
│ queries.ts        读路径唯一入口与查询逻辑（统一接口调用）│
│ service.ts        写路径逻辑（统一接口调用）       │
│ validators.ts     校验规则（zod，单一来源）        │
```

## 数据流向

```
React UI (src/features/)
    │ 用户交互触发事件
    ▼
Store (src/stores/, authClient.useSession)
    │ zustand action 更新本地状态, 经 fetch 调用统一接口
    ▼
统一接口 (src/app/api/)
    │ 会话校验, zod 复验, 错误归一, 路由到对应业务逻辑
    ▼
Service / Queries (src/modules/)
    │ 执行业务逻辑, 调用 DB model
    ▼
DB Model (src/db/)
    │ 封装 Drizzle ORM 查询
    ▼
PostgreSQL
```
