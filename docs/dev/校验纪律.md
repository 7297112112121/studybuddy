# 校验纪律

涵盖校验规则归属与单一来源、双端共用、校验落点、失败表达与 wire 格式收口——凡编写或修改产品代码涉及输入校验的技能在每任务提交前逐条自查的裁判文档。本文件是校验规则的真源,规则**包括但不局限于**以下条目,新增校验规则登记于此。

## 规则单一来源

- 校验规则真源唯一:校验层(`src/validation/`,平铺,按域命名 `<域>.ts`)集中各域校验规则——界限常量、正则、严格语义判定与 wire 解析/序列化纯函数;wire 契约(zod schema 与出入参类型)落统一接口路由目录 `src/app/api/<域>/request.ts`(请求契约)与 `response.ts`(响应契约),不带域命名;规则与 schema 界限禁止在任何消费方复写字面值,消费方一律引用导出成员;
- 响应契约只描述 wire 现状,不复用请求侧字段规则(如长度上限),避免历史数据被读路径误杀;
- 规则判定以 zod schema 为表达形态:提交门与复验一律经 schema,谓词与格式函数(isValid* 等)只服务 schema refine 与 wire 判定,消费方不另写平行的纯函数校验链(存量纯函数校验链已删除,勿回流);
- 校验层是纯叶子:只依赖外部包与 common(如 `@/common/date`),禁止依赖业务层(modules/features/app);路由目录契约文件依赖校验层与 zod,业务侧引用单向(modules/features/stores/契约切面 → 路由目录契约文件与校验层),判定实现不引入校验层↔service 成环(如周一判定内联日期数学,不调 service 的周锚点工具);
- 规则界限与下游配置同源注入:同一组界限常量注入正则量词、Better Auth 插件配置与规则浮层文案插值(如账户名/密码长度),改一处全链生效,禁止旁路直写;
- 消歧备案:`src/db/schema.ts` 是 drizzle 表定义,与校验契约层不同义。

## 双端共用

- 同一入参的客户端提交门与服务端复验引用同一 zod schema:客户端提交门(features/<m>/forms 的提交处理)不过则呈现字段错误、不提交;服务端复验在统一接口契约切面(`src/app/api/contract.ts` 的契约内核 runContract)完成,客户端通过不豁免服务端复验;
- 写端点 body 与读端点 query 均走 schema:路由把请求体/searchParams 折成普通对象交契约切面复验(如 calendarEntryInputSchema 与 calendarEntriesQuerySchema),query 的多臂(union)与解析直出(transform)在 schema 内表达;
- 备案:登录经 Better Auth 无服务端复验端点,登录表单 schema(loginFormSchema)仅作客户端提交门;注册 schema(registerFormSchema)双端共用;
- 校验规则的测试以 schema 断言为形态(safeParse 成败与产出),不在测试内复写规则界限。

## 校验落点

- 校验只发生在外部输入与 IO 边界:用户提交、统一接口入参(body/query)、地址栏参数格式约束;边界处用校验契约层设施收口,业务层(queries/service)不重复校验入参——入参复验是契约切面专属;边界之外不防御;
- UI 实时侦测(规则浮层、控件禁用)是纯呈现,经导入与 schema 同源衔接,维持不变量「实时拆解逐条全过 ⇔ schema 通过」;拆解判定居 features 层勿回流请求契约文件,请求契约文件不掺 UI 语义;
- 表单控件前置约束(maxLength、控件禁用)是 UX 减负,不构成校验豁免:服务端 schema 仍兜底同界限(如标题上限、开始留空则结束禁用)。

## 失败表达

- zod message 直接承载 i18n 文案键(如 calendar.error.invalidDate),禁止裸文案,键与 locales 文案组对齐;
- 字段级错误统一经 toFieldErrors(`src/common/error.ts`)折算,消费方不自行解析 ZodError;字段错误类型的键随 schema 字段推导(如 CalendarFieldErrors),表单字段名与 schema 字段名不一致时显式枚举键全集(如 AuthMessageKey)并注明同步义务;
- 服务端复验不过归一输入无效(INVALID_INPUT)并携带字段级错误(fieldErrors);客户端提交门不过只呈现字段级文案,不发请求。

## wire 格式收口

- wire 格式(日期 "YYYY-MM-DD"、年月 "YYYY-MM"、时刻 "HH:MM")的解析、序列化与严格语义判定(真实日历日、周一锚点、年月范围)收口校验契约层(parseYearMonth/formatYearMonth/isValidDateString 等),双端传输一律经收口成员,不手写拼接与解析;
- 时刻契约单一来源:格式正则(TIME_HHMM_RE)由 schema 校验与时刻换算共用,禁止另立正则;
- 口径备案:月份为产品口径 1~12,不是 JS Date 的 0~11。

## 外来形态(校验侧)

- Better Auth 是适配非豁免:用户名/密码界限经常量注入其插件配置,同源不旁路;唯一冲突结果折算为契约化错误(USERNAME_ALREADY_REGISTERED)进入统一错误词汇;
- 引入其他带内建校验的第三方(表单库、存储 SDK 等)时,先在对应域校验层(`src/validation/<域>.ts`)登记规则单一来源,第三方配置引用同源界限,禁止双写。
