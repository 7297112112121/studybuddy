# 异常处理纪律

涵盖异常分类、码登记、抛出与捕获、留痕与客户端消费规则——凡编写或修改产品代码涉及失败路径的技能在每任务提交前逐条自查的裁判文档。本文件是异常处理规则的真源,规则**包括但不局限于**以下条目,新增异常规则登记于此。

## 异常分类

- 业务报错(契约码):可预期的领域规则、输入与会话状态拒绝;码登记于各层 error.ts,经契约化错误(ApiError)抛出,客户端按码分支处理;
- 技术报错(兜底码):未预期的系统故障(数据库、缓存、代码缺陷);码只有保存失败(SAVE_FAILED)与加载失败(LOAD_FAILED)两个,一律由契约切面归一产生,HTTP 状态一律 500;
- 契约码只能由业务层显式抛出,兜底码只能由切面归一产生:业务层遇未预期异常直接放行,禁止主动抛兜底码,禁止捕获后自行转译成兜底码。

## 码登记

- 公共契约码(API_ERROR)登记于 `src/common/error.ts`,只收跨域语义:输入无效(INVALID_INPUT)、未授权(UNAUTHORIZED)、未找到(NOT_FOUND)与两个兜底码;域码登记于 `src/modules/<域>/error.ts`,认证技术域登记于 `src/auth/error.ts`;码为「常量与类型同源」的字面量,不建逐码错误类;
- 错误码与 HTTP 状态码同处登记:公共码映射(API_ERROR_STATUS)在 `src/common/error.ts`,域码映射(如 AUTH_ERROR_STATUS)在该域 error.ts;`src/app/api/contract.ts` 汇总各层映射并以错误码全集类型约束完备性,新增错误码未补状态即编译报错;
- 判定错误形态用的协议错误码(如 PG sqlstate)同登记于所在域 error.ts,判定处引用常量而非裸字面量。

## 抛出与捕获

- 业务层与基础设施层任意深度 throw,不做局部兜底;中层捕获仅允许判定折算:捕获后识别已知特征(如唯一约束冲突)折算为契约化错误(ApiError)再抛出,识别失败必须原样 rethrow;
- 异常翻译只发生在边界,共三类:统一接口契约切面(`src/app/api/contract.ts`)、React 渲染边界(error.tsx 与 global-error.tsx)、客户端提交边界(表单提交与请求编排判别);
- 业务层禁止构造响应体判别联合(ApiResult)与 Response,拼装是切面专属。

## 会话语义

- 会话查询(getCurrentSession)仅「无有效会话」返回 null;查询异常向上抛,由所在边界归一:统一接口按方向归一为兜底码;未授权(UNAUTHORIZED)只表达真未登录。

## 统一接口切面

- 契约切面两变体(有会话/无会话)首参收请求(request),方向由请求方法推导:读端点(GET)归一加载失败(LOAD_FAILED),写端点(其余方法)归一保存失败(SAVE_FAILED);方向不在调用侧手写;
- 切面归一技术报错前必须留痕:经服务端日志(logger)记录原始异常,方向与捕获阶段(session/operation)作结构化字段;原始 message 与 cause 不进响应体;
- 业务报错不留痕:业务事实不是故障。

## 留痕

- 服务端留痕唯一载体为结构化日志(logger,pino 单例,JSON 行写 stdout);客户端留痕用 console.error,浏览器不引入 pino;
- 留痕 msg 只描述故障事件本身(何处捕获、发生了什么),不写处理动作(归一成哪个码);
- 留痕只发生在归一点与适配点。

## 客户端消费

- 可预期失败走统一接口判别联合(ApiResult)按码分支;fetch reject 与响应解析异常由统一接口客户端契约切面(src/api/contract)的请求封装按方向归一为兜底码并留痕,不向调用侧抛出;契约失败结果统一经该切面的失败分支策略分派,未授权(UNAUTHORIZED)由策略统一跳登录;
- 渲染失败走 React 边界(error.tsx 与 global-error.tsx):边界只呈现通用文案与重试,留痕 console.error,不向用户呈现 error.message;
- 兜底码的呈现文案键必须存在并纳入逐字锁定(码与文案键对齐)。

## 外来错误形态适配

- 第三方错误形态(better-auth 服务端 APIError 类、客户端 resolve 不 reject 的 `{ status }` 裸对象)进入项目前必须经适配点折算成项目词汇;
- 认证技术的唯一适配点在 `src/auth/error.ts`:feature 层禁止直接解读裸 `{ status }` 对象,只消费折算后的文案键;登录与登出管道经适配器消费,不走统一接口判别联合;
- 引入其他强形态第三方(支付、存储 SDK 等)时,先在对应层登记适配点与折算规则,再接线。
