# ADR-0020：镜像仓库采用腾讯云 TCR 个人版

## 状态

已接受（Accepted）

## 日期

2026-11-12

## 背景

- 本 ADR 由 ADR-0018 拆分而来，决策事实与证据均于 2026-11-12 确立。
- 部署面为两台腾讯云国内轻量应用服务器（2核4G 与 4核4G，各 50G 存储、300G/月流量），跑 ADR-0016 定下的单机 Compose 拓扑。镜像的**读者**就是这两台部署机——镜像的消费者在哪，registry 就该在哪。
- 开源项目零持续成本取向：仓库为 GitHub 公共仓库，CI 已定为 GitHub Actions（ADR-0018），镜像仓库同样不能引入月度账单。
- 腾讯云 TCR 个人版的官方定位三连：计费概述原文"个人版服务面向个人开发者，限额免费使用，不承诺 SLA 及相关补偿"；层级说明原文"个人版服务为云上共享服务，即所有个人版用户将共享服务后端及数据存储，且镜像托管及上传下载具有配额限制。容器镜像服务个人版不收取费用"。

## 决策

镜像仓库采用**腾讯云 TCR 个人版**（`ccr.ccs.tencentyun.com`，命名空间 `studybuddy`）。

- **tag 策略**：日常推送 tag = 短 SHA；发版时附加 semver tag——与 ADR-0018 的 `v*` tag 触发生产部署对应，回滚即重放历史 tag 的部署作业。
- **登录凭证**：TCR 采用固定密码模型，登录凭证按 GitHub environment 分环境存放，细节见 ADR-0022。
- **配套姿势**：TCR 个人版无内置镜像安全扫描（官方文档将安全扫描列为 TCR 企业版功能），扫描在流水线内做（ADR-0021）——这正是个人版免费的正确配套姿势。

## 备选方案

### 镜像仓库：GHCR（GitHub Container Registry）
- 优点：免费、与 Actions / GITHUB_TOKEN 原生集成，零额外凭证。
- 缺点：端点在境外——镜像的**读者**（两台国内腾讯云服务器）每次部署都要跨境拉取，链路稳定性与速度不可控、无任何 SLA。
- 否决原因：镜像的消费者在哪，registry 就该在哪；TCR 与部署机同在腾讯云境内。

### 镜像仓库：Docker Hub
- 优点：生态默认，公共仓库免费。
- 缺点：官方限流文档明示"Unauthenticated users 100 per IPv4 address or IPv6 /64 subnet"；端点境外同上。
- 否决原因：限流 + 跨境双输。

### 镜像仓库：阿里云 ACR 个人版
- 优点：同为国内大厂、有个人免费层。
- 缺点：服务器在腾讯云，跨厂商拉取链路；无任何相对 TCR 的增益。
- 否决原因：同地域同厂商是 TCR 的独占优势。

### 镜像仓库：Harbor 自托管
- 优点：功能最全（内置扫描、复制、P2P 分发），完全自持。
- 缺点：2核4G 上再养一个生产级服务 + 存储后端；又一个升级守护面。
- 否决原因：薄基础设施；个人版免费层已覆盖本项目全部需求（推/拉镜像 + 固定密码认证）。

### 镜像仓库：TCR 企业版（基础）
- 优点：独享后端、SLA、内置安全扫描、内网访问链路完善（官方文档）。
- 缺点：包年包月 / 按量计费、存储另走 COS 计费——为开源个人项目引入持续成本；本项目镜像为应用代码不含用户数据，共享后端不触碰 ADR-0005 数据自持边界。
- 否决原因：成本不成比例；列入观察名单——项目商业化后升级路径平滑（同命名空间同地域迁移）。

## 后果

### 正面
- TCR 与部署机同在腾讯云境内，拉取链路不跨境；个人版官方支持部分地域（北京、上海、成都等）跨地域内网访问，服务器地域若在列可进一步走内网。
- **零持续成本**：个人版官方原文"不收取费用，可直接开通使用"，与开源项目取向一致。

### 负面
- TCR 个人版是**共享后端、限额使用、不承诺 SLA**（官方原文三连）——镜像托管与上传下载有配额上限；registry 故障即部署通道阻塞。缓解：tag 可重推，本地构建 + `docker compose up --build` 逃生步骤写入 runbook。

### 风险
- TCR 固定密码无自动轮换；季度轮换入回顾清单（ADR-0013 / 0015 同款纪律）。
