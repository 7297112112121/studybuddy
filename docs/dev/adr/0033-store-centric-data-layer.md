# ADR-0033：客户端数据层采用 store 居中与统一 HTTP 接口

## 状态

已接受（Accepted）

## 日期

2026-11-24

## 背景

- 客户端数据场景从表单突变扩展为全量读写：页面主体客户端化后，组件对服务端数据有统一的订阅与失效诉求。
- 既有形态中 RSC props 下行与 Server Action 上行并存，读写两端传输心智割裂；服务端数据在客户端无持有层，跨组件共享靠 props 逐层传递，失效编排分散在 revalidatePath 与各调用点，漂移无单一收拢点。
- 形态约束：React 服务端组件无法触碰浏览器内 store，store 居中的数据流要求页面主体客户端化，page 退化为薄壳；本产品为登录后工具，无 SEO 诉求，客户端化代价可接受。
- 开发者裁定单一流约束：通往服务端的数据通路只允许一条，认证与 AI 流式为统一接口的段，不另立通道。

## 决策

客户端数据层采用 store 居中与统一 HTTP 接口：

1. 数据流单线：业务组件（src/features/）只订阅 store；store 经 fetch 调用统一接口读写服务端数据，统一接口路由到业务逻辑层（src/services/ 的 queries/service）后落数据库；禁止组件绕过 store 直连服务端数据；
2. 统一接口为自写 Route Handler（物理落点 src/app/api/）：每端点强制会话校验、zod 复验、错误归一，共享胶水保持单一来源；
3. 服务端数据的客户端持有层为 zustand（状态库职责重新划定：服务端数据入 store）：store 按业务域切片，写入经 store action 更新本地状态并发起请求，失效编排（登出、过期、写后重取）由 store 层承担；
4. RSC 不做数据获取：页面为客户端薄壳；服务端守卫相应转为客户端会话判断（会话态经 Better Auth 客户端内建响应式 store 订阅），安全边界完全落在统一接口逐端点会话校验上；
5. 错误协议沿用判别联合：统一接口返回 `{ ok: true, data } | { ok: false, error }`，调用侧分支消费；传输层错误（fetch reject）由调用侧归一，不向 React 边界抛裸异常；
6. 不引入客户端数据缓存库（TanStack Query、SWR）：服务端数据的客户端缓存真源就是 zustand store，第二套缓存层与之重叠；
7. 入参校验单一来源：schema 从数据库表结构推导，统一接口入口以 zod 复验。

## 备选方案

### 维持 RSC 直读 + Server Actions 分工

- 优点：首屏数据随 HTML 直达，零客户端请求；传输层全部为 Next/React 原生形态。
- 缺点：读写两条传输形态并存；服务端数据无客户端持有层，跨组件共享与失效编排各自为政；RSC 与客户端组件边界靠 props 逐层衔接。
- 否决原因：与单一流约束正面冲突；数据流割裂正是本次要消除的现状。

### TanStack Query 承担客户端缓存层

- 优点：缓存、请求去重、失效编排有一等公民 API，devtools 成熟。
- 缺点：多一套运行时依赖与缓存心智，与 zustand 持有层职责重叠。
- 否决原因：服务端数据的客户端真源已定为 zustand store，第二套缓存层冗余。

### 全部请求继续走 Server Actions

- 优点：无 HTTP 层，类型全程推断。
- 缺点：每客户端串行分发，同屏多查询总时延累加；均为 POST，无 GET 缓存语义；无法承载流式与轮询形态。
- 否决原因：统一接口需以 HTTP 语义承载读、写、流三形态，Server Actions 只覆盖突变。

## 后果

### 正面

- 通往服务端只有一条数据流（features → store → 统一接口 → 业务逻辑层 → PostgreSQL），读写同构，心智单一。
- 服务端数据的客户端持有与失效编排有唯一收拢点（store 层）。
- 端到端类型链保持：数据库表（Drizzle）→ zod → 业务逻辑层 → 统一接口导出类型 → store，改表时客户端报错即时暴露。

### 负面

- 首屏数据不再随 HTML 直达，加载期出现取数态；服务端渲染的 SEO 能力放弃。
- 服务端守卫移除后未登录用户可拿到页面壳，安全边界完全依赖统一接口逐端点校验，纪律成本上移。
- store 失效编排自维护：登出/过期/写后重取三处失效无库编排，是长期纪律负担。

### 风险

- store 服务端数据切片的失效编排复杂度随业务域增长，首个业务域迁移完成后需回顾，必要时以新决策收敛。
- 首屏取数时延与请求瀑布需在实现期以真实场景验证。
