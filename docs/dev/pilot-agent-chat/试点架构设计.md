# 试点架构设计：AI 操控客户端页面与工具实现位置

## 状态

草案（试点验证中）

## 背景

- 云端 python AI 服务无浏览器自动化（有意约束）：AI 操控客户端页面的能力面收敛为声明式工具，不触碰任意 DOM。
- 链路拓扑与流式通道已定（ADR-0030）：前端只连 Next，python 仅内网，SSE 全链。
- 前端 UI 流式渲染采用 AI SDK（ADR-0031）：AgentEvent 到 UIMessage 协议的映射由 Next 加工层承担。
- 持久化唯一归口 Next 业务逻辑层（ADR-0034）：python 无持久层，工具数据面出口唯一经内网 API。
- 前端为 store 居中架构：store action 调请求层取数写自身，写流程链（forms）内建校验。
- 框架机制（AgentScope 2.0.12 实装）：`ToolBase.is_external_tool=True` 的工具不本地执行——模型发起调用时 reply 进入 park 态并发出 `REQUIRE_EXTERNAL_EXECUTION` 事件；执行方回传 `EXTERNAL_EXECUTION_RESULT` 后 resume 继续推理。

## 客户端能力协议（external tool 家族）

统一契约模板（新增一个工具 = 两侧各一次模板实例化）：

- python 侧声明模板：`ToolBase` 子类，`is_external_tool=True`，无 `__call__`；仅声明 name/description/params schema。
- wire 契约：`REQUIRE_EXTERNAL_EXECUTION` 帧（`tool_calls: name + args`）→ 前端执行器执行 → `POST /chat/external-result` 回传 `{tool_call_id, output}` → `ToolResultBlock` → resume。
- 前端执行器模板：`handlers: Record<toolName, (params) => Promise<result>>` 注册表；执行结果按各工具 result schema 回传。

首版工具家族：

| 工具 | 参数 | 前端行为 | 回传 |
|---|---|---|---|
| navigate | target_route | router.push（typedRoutes Route 类型约束） | 目标路由 |
| read_page_state | （无） | 白名单 store 摘要：当前路由、当前页域关键状态 | 摘要 JSON |
| submit_form | form_id, values | 经既有 forms 写链执行（校验内建） | 写结果摘要 |

安全边界：执行以用户会话身份进行；读取范围为白名单摘要，禁止任意 DOM/存储读取；高危操作可叠加框架 `REQUIRE_USER_CONFIRM` 确认帧。

## 工具实现位置三方案

问题：AI 产生的数据变更如何让前端 store 感知并刷新。

| 维度 | 一 服务端实现 | 二 客户端实现 | 三 读写分流混合 |
|---|---|---|---|
| 工具落点 | 全部 python→内网 API | 数据变更类全部 external，前端 forms/store 写链执行 | 查询/只读服务端，变更类客户端 |
| store 一致性 | 需新增变更通知机制（会话流附加 domain 失效帧→前端失效重取） | 自动一致（复用既有写链，UI 即时反映） | 变更类自动一致；只读类无需 |
| 无头可用（定时/后台） | 可用 | 不可用（无执行器） | 查询类可用，变更类不可用 |
| 模型反馈闭环 | 同步单跳 | 回传多一跳 RTT | 分流各自闭环 |
| 职责归属 | python tool/+adapters，前端仅加失效订阅 | 前端新增执行器模块；python 仅声明 | 两侧模板并存+分流纪律 |
| 模板成本 | 一套模板 | 一套模板 | 两套模板+命名纪律防漂移 |

## 裁决点

- 主裁决：三方案取一（建议：三，即「查询服务端 + 变更客户端」读写分流）。
- 子裁决（若变更类走客户端执行）：落库写由前端 forms 写链执行（store 自动一致，绑前端在线）或服务端 adapters 执行（无头可用，需变更通知机制补 UI 感知）。

## 试点落点（pilot_chat.py）

- 服务端工具模板实例 ×1：get_study_stats（stub，标注正式形态经 adapters）。
- 外部工具模板实例 ×3：navigate / read_page_state / submit_form（声明形状）。
- 端点：POST /chat（SSE 流）、POST /chat/external-result（回传恢复）、GET /health。
- 验收：打字机帧流；查询工具参与推理；external park/resume 闭环含 read_page_state 回传被模型消费。
- 试点不做：storage 三件套（组装形态待裁决）、Mem0/RAG、回放/多订阅、鉴权映射、Next 侧映射层。
