# 试点架构设计：AI 操控客户端页面与工具实现位置

## 状态

修订稿 v2（v1 → v2：并入行业调研结论与两项裁决）

## 裁决记录

- 主裁决：方案三读写分流——查询/只读工具在 python 服务端实现（经内网 API 走 Next），变更类工具 external tool 前端执行。
- 子裁决：落库写由前端 forms 写链执行（store 自动一致；无头场景未决，待真实写工具特性设计时再议）。

## 背景

- 云端 python AI 服务无浏览器自动化（有意约束）：AI 操控客户端页面的能力面收敛为声明式工具，不触碰任意 DOM。行业印证：Playwright MCP 等浏览器自动化定位为开发者自动化且官方自认「不是安全边界」（有 CVE 前科）；面向终端用户的嵌入式助手主流为受限声明式 action（CopilotKit/AG-UI/HITL 确认流）；白名单工具把注入攻击面收窄为参数校验。
- 链路拓扑与流式通道已定（ADR-0030）：前端只连 Next，python 仅内网，SSE 全链。
- 前端 UI 流式渲染采用 AI SDK（ADR-0031）：AgentEvent 到 UIMessage 协议的映射由 Next 加工层承担。依赖现状修正：`ai`/`@ai-sdk` 按该 ADR 已接受但尚未引入，引入动作在前端接线特性分支执行；API 名以引入时随包文档为准（addToolOutput / sendAutomaticallyWhen，勿用已废弃旧名）。
- 持久化唯一归口 Next 业务逻辑层（ADR-0034）：python 无持久层，工具数据面出口唯一经内网 API。
- 前端为 store 居中架构：store action 调请求层取数写自身，写流程链（forms）内建校验。
- 框架机制（AgentScope 2.0.12 实装）：`ToolBase.is_external_tool=True` 的工具不本地执行——模型发起调用时 reply 进入 park 态并发出 `REQUIRE_EXTERNAL_EXECUTION` 事件；执行方回传 `EXTERNAL_EXECUTION_RESULT` 后 resume 继续推理。

## 客户端能力协议（external tool 家族）

统一契约模板（新增一个工具 = 两侧各一次模板实例化）：

- python 侧声明模板：`ToolBase` 子类，`is_external_tool=True`，无 `__call__`；仅声明 name/description/params schema。
- 工具 schema 双端同源：单一 schema 来源，前端注册表与 python 声明均由其派生（防「声明在服务端、执行在前端」漂移——CopilotKit 跨协议转发不可靠的前车之鉴）。
- wire 契约：`REQUIRE_EXTERNAL_EXECUTION` 帧（`tool_calls: name + args`）→ 前端执行器执行 → `POST /chat/external-result` 回传 → `ToolResultBlock` → resume。
- 回传契约（含失败通道）：`{tool, toolCallId, output, state: 'output-available' | 'output-error', errorText?}`——失败必须可辨（AG-UI ToolMessage 语义：无失败标记则成败不可分）。
- 变更类工具 output 形状：`{ok, affectedKeys: string[], summary?, fieldErrors?}`——affectedKeys 为 zustand 失效刷新的数据源（AG-UI StateDelta 思路轻量化：只传受影响资源 key，不做状态镜像同步，守 ADR-0034）。
- 前端执行器模板：`handlers: Record<toolName, (params) => Promise<result>>` 注册表。
- 执行纪律：变更类工具串行执行、按 toolCallId 有序回传防竞态；回传 API 不 await（AI SDK 官方警告防 deadlock）；恢复触发等价 `sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls`（全部工具结果就绪自动续跑）。

Next 映射目标：`REQUIRE_EXTERNAL_EXECUTION` → AI SDK typed tool part `tool-<name>`（args 流式为 input-streaming，完成后 input-available）；`REQUIRE_USER_CONFIRM` → askForConfirmation 形状（确认结果即该工具 output，resume 后续跑），不用 toolApproval（服务端执行工具的审批，与前端执行异构）；AI SDK 有审批伪造警示——未来 python 直执高危工具时需服务端验证机制等价物。

首版工具家族：

| 工具 | 参数 | 前端行为 | 回传 output |
|---|---|---|---|
| navigate | destination（路由白名单枚举，防幻觉路由） | router.push（typedRoutes Route 类型约束） | `{ok, destination}` |
| read_page_state | （无） | 白名单 store 摘要：当前路由、当前页域关键状态 | `{ok, summary}` |
| submit_form | form_id, values | 经既有 forms 写链执行（校验内建，不绕过） | `{ok, affectedKeys, summary?, fieldErrors?}` |

安全边界：执行以用户会话身份进行；读取范围为白名单摘要，禁止任意 DOM/存储读取；高危表单可叠加 importance 分级确认（AG-UI confirmAction 范式，框架 `REQUIRE_USER_CONFIRM` 帧承载）。

## 工具实现位置三方案

问题：AI 产生的数据变更如何让前端 store 感知并刷新。

| 维度 | 一 服务端实现 | 二 客户端实现 | 三 读写分流混合（已裁定） |
|---|---|---|---|
| 工具落点 | 全部 python→内网 API | 数据变更类全部 external，前端 forms/store 写链执行 | 查询/只读服务端，变更类客户端 |
| store 一致性 | 需新增变更通知机制（会话流附加 domain 失效帧→前端失效重取） | 自动一致（复用既有写链，UI 即时反映） | 变更类自动一致；只读类无需 |
| 无头可用（定时/后台） | 可用 | 不可用（无执行器） | 查询类可用，变更类不可用 |
| 模型反馈闭环 | 同步单跳 | 回传多一跳 RTT | 分流各自闭环 |
| 职责归属 | python tool/+adapters，前端仅加失效订阅 | 前端新增执行器模块；python 仅声明 | 两侧模板并存+分流纪律 |
| 模板成本 | 一套模板 | 一套模板 | 两套模板+命名纪律防漂移 |

服务端写失效信道（预留）：若未来出现 python 直写，参照 vercel/ai-chatbot 的流内自定义 data part 形状（写库后同流夹带失效信号，前端缓存失效重取）；禁止用 STATE_SNAPSHOT/STATE_DELTA 同步业务数据镜像（其语义是 agent 内部状态同步，且会造成 python 持业务数据镜像，违 ADR-0034）。

## 帧协议对齐

试点自定 SSE 帧沿用框架形状（`data: {json}\n\n`，事件名靠 JSON `type` 字段）；字段语义对齐 AG-UI（run/toolCallId/delta/error）保留迁移路径。venv 已装 ag-ui-protocol 1.0.0（Python EventEncoder 即 `data: {json}\n\n`），后续若选直接引入协议零成本。

## 试点落点（pilot_chat.py）

- 服务端工具模板实例 ×1：get_study_stats（stub，标注正式形态经 adapters）。
- 外部工具模板实例 ×3：navigate / read_page_state / submit_form（声明形状）。
- 端点：POST /chat（SSE 流）、POST /chat/external-result（回传恢复）、GET /health。
- 验收：打字机帧流；查询工具参与推理；external park/resume 闭环含 read_page_state 回传被模型消费；回传 state='output-error' 的失败分支对模型可辨。
- 试点不做：storage 三件套（组装形态待裁决）、Mem0/RAG、回放/多订阅、鉴权映射、Next 侧映射层、前端依赖引入。

试点实施事实（验收时对 2.0.12 实装核对）：

- 外部工具子类须显式设 `is_concurrency_safe` 与 `is_read_only`：基类仅注解无默认值，缺省在 Acting 阶段报 `AttributeError`。
- `check_permissions` 为抽象方法：客户端执行工具恒放行，执行即用户行为，与内置 AskUser 同理。
- `FunctionTool` 缺省逐次请求确认（`permission=None`）：只读查询工具以 `permission=ALLOW` 预放行。
- 流结束且无 `REPLY_END` 帧即停靠待回传；同一 reply 可多轮停靠/恢复。
- 失败通道以 `ToolResultState.ERROR` 回传，模型可辨并如实转述。
