# Proposal: AXY-8 登录注册

| 对应用户故事 | [AXY-8 登录注册](../../product/auth) | 状态 | 已批准 |
| ---- | ---- | ---- | ---- |
| 日期 | 2026-11-14 | 批准人 | 海渝（2026-11-14） |

## 目标与背景

刚决定认真学一门课的学生需要一个属于自己的账号，让计划、进度和打卡只认本人，换设备也能接着走（故事主干）。本特性交付手机号注册、手机号/邮箱格式登录、会话与路由守卫的完整闭环，是全部业务故事（AXY-11 信息录入、AXY-12 工作台等）的前置入口。

## 范围（做什么）

- 登录视图（`/login`）：手机号/邮箱 + 密码 + 协议勾选，字段级与汇总校验，登录成功进入工作台。
- 注册视图（`/register`）：手机号 + 密码 + 确认密码 + 协议勾选（验证码字段本期隐藏），注册即登录并进入工作台。
- 会话管理：退出登录、会话失效、已登录访问登录/注册页的回退守卫。
- 账号数据与安全：密码不可逆摘要、手机号唯一索引、协议版本与同意时间落库。
- UI 行为与 [线框图](../../product/auth) 逐屏一致（登录/注册视图切换、密码可见性、提交中状态、占位入口）。

## 非目标（不做什么）

| # | 不做 | 理由 |
| - | ---- | ---- |
| 1 | 短信验证码的发送与校验 | DOR 已声明验证码通道延迟，本期无外部服务依赖；通道就绪后另立迭代恢复字段与校验 |
| 2 | 找回密码 | 依赖短信验证码通道做身份核验；线框图「忘记密码?」入口保留为占位（已与提出者确认，2026-11-14） |
| 3 | 第三方登录（微信登录、手机号一键登录） | 线框图即标注「本期不做，仅占位」，UI 呈禁用占位态 |
| 4 | 邮箱注册 | 本期仅手机号注册（已与提出者确认）；登录框仍接受邮箱格式（AC-3），提交后按账号不存在处理 |
| 5 | 《用户协议》《隐私政策》正文内容与法务审阅 | 本期仅落库协议版本与同意时间，链接为占位 |
| 6 | 2FA、魔术链接、组织等 Better Auth 插件能力 | ADR-0013 约定按需启用，本期不开 |
| 7 | 「记住我」、多端会话管理界面 | 用户故事未涉及 |
| 8 | 企业/高校账号对接 | 线框图品牌区已标注本期不支持 |
| 9 | 新用户信息录入的引导与「跳过」交互 | PO 决策（2026-11-14）：建档业务与登录注册业务分离、互不打扰，新用户可录入也可跳过；录入入口的形式归属 AXY-11 / AXY-12 |

## 需求条目

每条可测试，终审逐条核对。来源标注用户故事 AC 编号或线框图（WF）。

| # | 需求 | 来源 | 验证方式 |
| - | ---- | ---- | ---- |
| R1 | 登录表单账号留空时提交：账号字段下方提示「请输入手机号或邮箱」，顶部汇总提示可见（按实际未通过项数计数），表单不提交 | AC-2 | E2E 测试 |
| R2 | 登录表单账号格式非法（如 10 位手机号、无后缀邮箱）时提示「格式不对：手机号 11 位，或 name@mail.com」；改填合法格式后该提示消失。合法形态：`^1[3-9]\d{9}$` 的手机号或 `本地名@域名.后缀` 的邮箱 | AC-3 | 单元测试（校验函数）+ E2E 测试 |
| R3 | 密码强度规则：8—20 位且同时含字母与数字；不符合（如纯数字 `12345678`、21 位超长）提示「密码为 8—20 位，需含字母与数字」。规则统一适用于登录框、注册框、确认密码框 | AC-5 | 单元测试（校验函数）+ E2E 测试 |
| R4 | 登录与注册均须勾选《用户协议》与《隐私政策》；未勾选提交时表单不提交，勾选框高亮为错误态 | AC-1 / WF | E2E 测试 |
| R5 | 提交中按钮转为加载态并禁用：登录按钮显示「登录中…」、注册按钮显示「注册中…」，加载期间不可重复提交 | AC-1 / WF | E2E 测试 |
| R6 | 登录成功后进入工作台，不依据建档状态分流：已建档与未建档账号行为一致 | AC-1 / AC-8（PO 修订 2026-11-14，见非目标 #9） | E2E 测试（已建档、未建档账号各验一例） |
| R7 | 登录失败统一文案：账号不存在、密码错误、密码为空（绕过前端校验直接提交）一律提示「账号或密码不对」；不得出现「密码错误」「该手机号未注册」等可探测账号存在性的差异文案 | AC-6 | 集成测试（接口层断言文案一致） |
| R8 | 注册表单字段为手机号、密码、确认密码、协议勾选（验证码字段本期隐藏）。手机号非法提示「请输入 11 位有效手机号」；确认密码为空或与密码不一致提示「两次输入的密码不一致」 | AC-4（提出者确认隐藏验证码，2026-11-14） | E2E 测试 |
| R9 | 注册成功：该手机号成为账号的登录手机号，自动登录并进入工作台，不强制进入信息录入页 | AC-4（PO 修订 2026-11-14） | 集成测试 + E2E 测试 |
| R10 | 已注册手机号再次注册：提示「该手机号已注册，去登录」，不产生第二个账号；提示中的「去登录」可切换到登录视图且账号框带入该手机号 | AC-4 / WF | 集成测试 + E2E 测试 |
| R11 | 退出登录：回到登录页，会话即刻失效（含 Redis 会话缓存）；此后直接输入工作台地址或浏览器后退均被重定向到登录页；重新登录后原账号与数据完好 | AC-7 | 集成测试 + E2E 测试 |
| R12 | 已登录访问 `/login` 或 `/register`：不渲染登录/注册表单；有浏览历史时自动返回上一页；新标签页直接打开（无历史可回退）时进入工作台 | AC-8（PO 修订 2026-11-14） | E2E 测试 |
| R13 | 密码只存不可逆摘要；任何接口与日志不出现明文密码 | DOD 工作项 | 查库与查日志各抽 3 条注册、登录记录 |
| R14 | 手机号在账号表上为唯一索引；并发提交同一号码注册仅一次成功，另一次得到「该手机号已注册」 | DOD 工作项 | 集成测试（同一号码并发两次注册） |
| R15 | 账号表记录协议版本与同意时间，注册成功时写入 | DOR 设计输入 | 集成测试（注册后查库断言两字段） |
| R16 | 登录/注册视图可在页内切换（顶部 tab 与底部链接），切换时已填表单值保留、错误提示清除 | WF | E2E 测试 |
| R17 | 登录与注册的密码输入框提供「显示/隐藏」明文切换 | WF | E2E 测试 |
| R18 | 第三方登录区按线框图呈现禁用占位按钮（微信登录、手机号一键登录），标注「本期不做，仅占位」 | WF | E2E 测试（存在性与禁用态断言） |
| R19 | 「忘记密码?」入口保留为占位：点击提示本期暂未开通，不进入找回密码流程 | WF（提出者确认，2026-11-14） | E2E 测试 |

| # | 指标 | 度量方式 | 豁免 |
| - | ---- | ------ | ---- |

## 边界与约束

| # | 边界 | 处理 |
| - | ---- | ---- |
| 1 | 手机号合法范围 `^1[3-9]\d{9}$`，注册框 `maxLength=11`，非该形态即拦截 | 前端与后端双重校验，文案见 R2/R8 |
| 2 | 邮箱仅为登录输入的合法形态，本期无邮箱账号；邮箱提交走 R7 统一失败文案 | 不做邮箱存在性探测 |
| 3 | 密码 8—20 位、同时含字母与数字（`(?=.*[A-Za-z])(?=.*\d)`），三处输入框规则一致 | 前端提示 + 后端拒绝 |
| 4 | 验证码字段本期从注册表单隐藏；短信通道就绪后在注册与找回密码流程中一并恢复 | 字段恢复属后续迭代，本期不做任何占位校验 |
| 5 | 会话遵循 ADR-0013：Better Auth 数据库会话 + Redis secondaryStorage；退出登录须同步失效 Redis 缓存会话 | 退出后旧会话访问任一受保护路由均被拒绝 |
| 6 | 受保护路由的未登录拦截在服务端完成，未登录响应中不得携带受保护页面内容 | R11/R12 的 E2E 用例覆盖 |
| 7 | 工作台与信息录入页路由路径以配置常量承载（路径由 AXY-12/AXY-11 定稿） | 本特性不硬编码具体路径字面量于多处 |
| 8 | 并发注册同一手机号由数据库唯一索引兜底，仅一次事务成功 | R14 集成测试验证 |
| 9 | 《用户协议》《隐私政策》链接为占位（不跳转正文），但勾选与落库（R15）真实生效 | 与非目标 #5 对应 |
| 10 | 与 AXY-12 的衔接：登录/注册成功后的目标页（工作台）若尚未实现，以占位路由承接 | 不影响本特性自身验收（见开放问题 #2） |
