# 接口测试纪律

涵盖接口轨真依赖与桩边界、期望值独立性、造号隔离、负空间与并发直证、直调基座与收尾、用例形态——凡编写或修改接口测试(tests/endpoint、tests/migrations)的技能在每任务提交前逐条自查的裁判文档。本文件是接口测试规则的真源,规则**包括但不局限于**以下条目,新增接口测试纪律登记于此。

## 真依赖与桩边界

- 断言目标恒为「端点直调 + 落库/缓存真值」:route handler 以 Request 直调不经 HTTP 层,数据库与 Redis 等基础设施永不桩接——真依赖直连是本轨存在意义,退回 mock 即降格为单测;
- 直调不覆盖 HTTP 分发层(URL 路由、方法分发、params 注入、Content-Type 处理),该回归由 e2e 轨承接,属已知空隙非缺陷;
- 桩仅限请求上下文的邻接读取(如会话读取),逐例重置禁跨例串态;
- 前置造号不是断言目标:注册可走 service、纯外键行可直插最小字段,断言目标恒为端点响应与库内真值。

## 期望值独立性

- 落库/读回断言以裸读表(select 直查)为期望来源,禁以被测链路自身的查询/服务层输出作期望——同源比对是恒真式,只证接线不证数据;
- 期望值用字面值与字面模板(占位邮箱格式、时间列原始形态"HH:MM:SS"),禁由实现函数推导;wire 全形状契约以响应契约 schema 复验收口,不与裸读重复锁形;
- 区间用例日期取固定真实日历日字面(月界/周界/跨月锚),禁相对当前时刻;会话时效以真实时钟核验新鲜度(晚于用例起点)——业务时间与时效核验两类不混。

## 造号与隔离

- 隔离靠唯一造号替代 teardown:账户名与资源 id 跨运行唯一,每例独立造号,任意单例可独立运行,不依赖前例遗留行。

## 负空间与并发直证

- 不可区分性以同值断言表达:安全上要求同文案的多情形用集合等价比较,差异字样负断言收口——逐情形断具体值即丢失「不可区分」本身;
- 越权与枚举面直证必须带库内回读:拒绝之外,原数据未动;
- 并发以 Promise.all 同键直证,断言与完成序无关(排序或集合比较);
- 双写链路双侧断言(库行+缓存键),失效验证多面齐删(响应、缓存键、库行)。

## 直调基座与收尾

- 直调基座(GET/POST 泛化、登录取 cookie)单一实现落 tests/endpoint/helpers,禁文件内私有复制——基座含 CSRF origin 处理语义,复制即漂移;
- 端点路径取自统一接口端点词汇(src/app/api/routes.ts 的 API_ROUTES 与动态段构造),禁再硬写路径字面量——origin 拼接留测试侧;
- 迁移由 globalSetup 自理,env 兜底与分轨配置一致,跑前基础设施在位;
- 连接收尾逐文件 afterAll 关闭自建连接(db.$client.end、redis.quit)——连接随文件 worker 隔离,禁依赖跨文件复用。

## 用例形态

- 独立行为拆例,同策略多路由可并例(如无会话各方法归一 401);
- 例名行为化(前置+行为+期望),禁位置序号前缀,需求溯源码除外;
- 迁移查证(tests/migrations)同轨执行,以真实库生成物断言。

执行层说明:存量文件不追溯整改,新写/被改到的文件按本约定执行。
