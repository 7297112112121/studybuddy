| 编号 | AXY-20 | 优先级 | P0 | 故事点 | 3 |

**状态**：已批准（2026-11-15 自 AXY-12 拆分设立，继承原批准范围；编号 AXY-20 由项目管理平台下发）

## 故事主干

**作为** 已经看见今天任务列表的本科学生，**我想要** 在同一页面把任务就地展开执行并打上完成卡，**以便** 做完一项勾一项，不切换任何应用。

## 目标 / 非目标 / 反目标

- **目标**：执行面板就地展开、页签切换与打卡状态机（进行中 / 已完成 / 撤销）全程不跳页。
- **非目标**：微课文档内容供给与题库建设（三桶 ❌ 占位，只交付交互壳）；「额外学一章」入口（归 AXY-12 空天态开放问题）。
- **反目标**：打卡状态写入独立的第二份进度数据——工作台与日历本各记各的账即失败（同一张日任务表）。

## 验收标准（AC）

> 本故事 AC 承接 AXY-12 拆分出的原 AC-3–AC-7（原文不变，编号按本故事重排）。

1. **给定** 第二行为「进行中 7/8 题」；**当** 点该行「继续」；**则** 该行仍为进行中，执行面板在任务列表下方就地展开，不跳页、不遮住其余两行；页签显示「① 微课文档」「② 刷题打卡 7/8」 〔走查：演示态 1〕
2. **给定** 执行面板停在微课页签；**当** 查看底部操作区；**则** 只有「收起」与「去刷题（8 题）」，不出现「完成本任务」；点「去刷题（8 题）」切到刷题页签并停在第 8 / 8 题 〔走查：演示态 2〕
3. **给定** 刷题页签，已完成 7 / 8 题；**当** 选一个错误选项；**则** 提示「答错了」并给出解析，已完成题数保持 7 / 8，「完成本任务」仍置灰；改选正确选项后题数变为 8 / 8 并提示「进度 +1 题」 〔走查：演示态 3〕
4. **给定** 刷题页签，已完成 8 / 8 题；**当** 点「完成本任务」；**则** 该行变「✓ 已完成」并出现「撤销」，抬头变「已完成 1 / 3」、进度条 33%；若当天仅此一项则抬头走全完成文案 〔走查：演示态 4〕
5. **给定** 三项依次打卡完毕；**当** 点第一行「撤销」；**则** 该行回「未开始」、题数清零，抬头与进度条回退为「已完成 2 / 3」与 67%，撤销不加二次确认 〔走查：演示态 5〕

### 各演示态契约

**演示态 1 · 执行面板就地展开**
- 入口：工作台任务列表（AXY-12 演示态 1）点「进行中」行的「继续」；
- 布局块：任务列表原样 → 其下方就地展开执行面板（页签头「① 微课文档」「② 刷题打卡 7/8」+ 页签正文 + 底部操作区）；
- 交互：当用户点「进行中」任务行的「继续」（行内按钮）时，系统在该行下方就地展开执行面板、不跳页、不遮住其余两行、被点行保持「进行中」，以实现同页执行不打断任务列表（AC-1）；
- 空态 / 边界：本期单面板——点其他行的操作按钮时面板切换目标行，不同时展开两个面板。

**演示态 2 · 执行 · 微课文档页签**
- 入口：演示态 1 停在「① 微课文档」页签；
- 布局块：页签正文（微课文档占位内容，见占位表）→ 底部操作区（「收起」「去刷题（8 题）」）；
- 交互：当用户查看微课页签底部操作区时，系统只提供「收起」与「去刷题（8 题）」、不出现「完成本任务」，以实现微课未读先刷题的顺序引导（AC-2 前半）；当用户点「去刷题（8 题）」（操作区按钮）时，系统状态转移切到刷题页签并停在第 8 / 8 题，以实现从微课到刷题的衔接（AC-2 后半）；当用户点「收起」（操作区按钮）时，系统收起面板、任务列表不变，以实现执行可随时中断；
- 空态 / 边界：微课正文为占位（惰性标注），不阻塞交互壳验收。

**演示态 3 · 执行 · 刷题打卡页签**
- 入口：演示态 2 点「去刷题（8 题）」；
- 布局块：题干与选项（占位题目，见占位表）→ 解析区 → 进度「7 / 8」→ 底部「完成本任务」（置灰）；
- 交互：当用户选错误选项（选项单选）时，系统提示「答错了」并给出解析、已完成题数保持 7 / 8、「完成本任务」仍置灰，以实现错答不计进度；当用户改选正确选项（选项单选）时，系统把题数更新为 8 / 8 并提示「进度 +1 题」，以实现刷题进度达到打卡门槛（AC-3）；
- 空态 / 边界：题目与解析为占位演示数据，判分逻辑（对 / 错 / 计数）照常验收。

**演示态 4 · 完成任务与全完成文案**
- 入口：演示态 3 完成全部题目后点「完成本任务」；
- 交互：当用户在 8 / 8 完成后点「完成本任务」（底部主按钮）时，系统把该行置为「✓ 已完成」并出现「撤销」、抬头变「已完成 1 / 3」、进度条 33%，以实现打卡完成与全局进度联动（AC-4）；当用户当天仅此一项任务时，系统抬头改走「今日任务已全部完成」全完成文案，以实现完成态反馈（AC-4）；
- 空态 / 边界：全完成文案为「今日任务已全部完成」语义（AC-4 引用），抬头与进度条同步。

**演示态 5 · 撤销回退**
- 入口：已完成任务行点「撤销」；
- 交互：当用户点已完成任务行的「撤销」（行内按钮）时，系统把该行回置「未开始」并题数清零、抬头与进度条回退为「已完成 2 / 3」与 67%、不加二次确认弹层，以实现误打卡即时回退（AC-5）；
- 空态 / 边界：撤销只回滚本任务，不影响其他已完成任务。
