## 故事主干

**作为** 想补技能但先修还没修完的本科学生，**我想要** 课程池明确标出哪些课现在就能学、哪些还差先修、差在哪，**以便** 不至于点进一门课学到一半才发现根本修不了。

## 目标 / 非目标 / 反目标

- **目标**：先修状态在列表与详情两处一致可见，拦截必带原因。
- **非目标**：学习状态四值的修改入口之外的任何课程数据管理；先修关系图的维护界面。
- **反目标**：静默隐藏先修未完成的课程——用户以为它不存在比看见「先修未完成」更糟。

## 验收标准（AC）

> 本故事 AC 承接 AXY-9 拆分出的原 AC-5–AC-8（原文不变，编号按本故事重排）。

1. **给定** 数据库原理与 SQL 的先修「数据结构与算法基础」为学习中；**当** 查看后端分组；**则** 该课位于后端组分隔条之后（未满足段）、带「先修未完成」标识，组头「可选 3 门」不含它；同段内按难度升序、再按时长升序排列（分布式系统设计排在其后） 〔走查：演示态 1〕
2. **给定** 数据库原理与 SQL 的先修「数据结构与算法基础」为学习中；**当** 打开该课详情；**则** 顶部提示先修未完成并列出未满足的课程名，「加入课程规划」不可用且写明需先完成「数据结构与算法基础」 〔走查：演示态 2〕
3. **给定** 算法复杂度与基础题训状态为待复习，动态规划专题依赖它；**当** 查看动态规划专题；**则** 该课无「先修未完成」标识、位于算法组可选段内，详情页先修行标「已满足 · 待复习」 〔走查：演示态 1〕
4. **给定** 数据结构与算法基础为学习中，数据库原理与 SQL 依赖它并因此带「先修未完成」；**当** 在详情页把该课状态改为「已完成」；**则** 该课显示为「已完成」；返回课程池后数据库原理与 SQL 的「先修未完成」标识消失、从组末移入可选段，后端组头可选数由 3 门变 4 门 〔走查：演示态 1〕

### 各演示态契约

**演示态 1 · 课程池列表（先修拦截视图）**
- 入口：课程池列表（AXY-9 演示态 1 的全量视图）；
- 布局块：沿用 AXY-9 分组列表；每组内以分隔条把课程分为「可选段」与「未满足段」，组头「方向 · N 门 · 可选 M 门」只统计可选段；
- 内容与数据形状：未满足段课程带「先修未完成」标识；段内排序难度升序、再按时长升序；
- 交互：先修课状态改为「已完成」后返回列表 → 对应课程的标识消失、从未满足段移入可选段、组头可选数 +1（AC-4）；「待复习」先修不触发标识（AC-3）；
- 空态 / 边界：某组全部未满足时组头「可选 0 门」，分段仍渲染。

**演示态 2 · 课程详情（拦截态）**
- 入口：在演示态 1 点开一门先修未完成的课；
- 布局块：顶部先修提示条 → 课程七项字段 → 先修行（逐门列出未满足课程名及其状态）→ 学习状态选择器（四值，详情页内可改——AI 裁定：AC-4 的状态修改入口由本故事详情态交付）→ 底部「加入课程规划」按钮（不可用）；
- 内容与数据形状：提示条写明未满足的先修课程名；按钮副文案写明需先完成的课程；
- 交互：「加入课程规划」不可用（AC-2）；先修全部满足时提示条消失、按钮可用（承接 AXY-9 详情）；
- 空态 / 边界：多门先修部分未满足时逐门列出，满足的门标「已满足 · 待复习」或「已满足 · 已完成」；先修全部满足时提示条消失、先修行保留（逐门标「已满足」）、按钮可用——详情页骨架（七项字段 + 加入按钮）由本故事交付（AI 裁定，AXY-9 只负责列表导航）。
