## 2. 目标与背景

日程里写了想做的事、却苦于找不到资料的本科学生,需要在日程条目上发起「帮我找资料」:由应用读懂条目意图,先给一份按天拆好、各带资料的安排清单,经删改确认后才写进日程,让日程里的事真的能做起来([故事陈述](./story))。这是应用第一个 AI 特性:AXY-22 proposal 非目标 #3 预留的「AI 自动排期接入」由此落地,但形态收敛为「AI 只提议、用户确认后写入」(D-01),不触碰日历「亲笔定下」的主人感。

## 3. 范围与非目标

### 3.1 范围(做什么)

- 在日程条目上发起「帮我找资料」:月视图当日详情(AXY-22)与周视图条目操作(AXY-23)两处入口(D-06)。
- AI 读懂条目意图,产出按天拆好的安排提案清单,每条含日期、安排文字与可直接打开的资料(D-01 / D-10);条目无可理解时间范围时 AI 先追问一句(D-05)。
- 提案删改确认后整单写入日程(D-12),原条目不变;资料随写入的条目留存可查(AC-3)。
- 边界行为:非学习类条目明确告知不适用;找不到资料连同理由告知;AI 服务不可用明确提示可重试(D-03 / D-04)。
- 数据归属:提案只读本人条目、写入只落本人日程(账号隔离)。

### 3.2 非目标(不做什么)

| # | 不做 | 理由 |
| - | ---- | ---- |
| 1 | 对话式 AI 助手入口(随手问输入框) | 发起只走条目级「帮我找资料」按钮(D-02);对话形态将来另立故事 |
| 2 | AI 自动发起(不经用户点击主动送提案) | 卡住与否用户自己最清楚,AI 替用户判断即打扰(D-02) |
| 3 | 「从哪天到哪天」跨度条目数据模型 | AI 按天成条即可表达范围;正式跨度条目将来另立故事(故事切割判定) |
| 4 | 资料收藏 / 评分 / 学习进度跟踪 | 本期资料只随条目留存;进度采集归执行采集类故事(D-08) |
| 5 | AI 服务配置界面(选模型 / 填密钥) | 服务与模型选型归技术侧,不向用户暴露(D-08) |
| 6 | 资料沉淀进个人知识库 / RAG | 本期资料只挂条目;知识库属产品闭环后续故事(D-08) |

## 5. 术语与路由

| 术语 | 含义 |
| ---- | ---- |
| 发起 | 在条目上点「帮我找资料」,触发 AI 读条目、出提案的动作(D-02) |
| 提案 | AI 产出的按天安排清单(界面临时态,不落库,D-13);每条提案项含日期 + 安排文字 + 资料 |
| 资料项 | 附于提案项 / 已写入条目的学习资料(标题 + URL,D-10) |

| 日程日历页 / 周视图 | AXY-22 / AXY-23 已批准界面,本特性在其上新增发起入口(D-06),不改其已批准行为 |

### 11.2 领域模型(四问与双向核对)

四问各成一表,正文引用实体、状态、事件时与本章口径一致;表结构的技术载体以 AXY-24 design 为准,本节只持产品口径。

**概念与状态**

| 实体 | 属性 | 状态 | 状态流转 |
| ---- | ---- | ---- | ---- |
| 条目(沿用 AXY-22) | 归属账号、所属日期、事项文字、可选开始 / 结束时间 | 已记录(唯一状态,不变) | 无:本特性不改条目生命周期 |
| 资料项(新实体) | 归属条目、标题(F-04)、URL(F-05) | 已留存(唯一状态:随确认写入落库,随条目删除而消失) | 无 |
| 提案(界面临时实体,不落库,D-13) | 来源条目、提案项列表(日期 F-03 + 文字 F-02 + 资料项) | 生成中 → 待确认 → 已确认 / 已放弃 | 生成中→待确认:AI 产出;待确认→已确认:确认写入;待确认→已放弃:关闭 / 重新生成覆盖;生成中→已放弃:关闭浮层 |

**状态义务**(没人须行动的状态不是队列)

| 状态 | 谁须行动 | 义务 | 关联 |
| ---- | ---- | ---- | ---- |
| 提案·待确认 | 用户 | 删改后确认写入,或放弃 / 关闭——提案不确认不落库(D-01) | R4、R10 |
| 提案·生成中 | 系统 | 生成完成转待确认,或失败转 E-03 / E-04 提示;期间不得写入日程 | R2、R7、R8、R10 |
| 条目·已记录 / 资料项·已留存 | 无人 | 纯记录状态,不构成须行动队列(沿用 AXY-22「不催办」口径) | AXY-22 非目标 #2 |

**领域事件**

| 事件(领域语言) | 触发 | 结果 | 关联 |
| ---- | ---- | ---- | ---- |
| 资料提案发起 | 在本人条目上点「帮我找资料」(D-02) | 进入提案流程:有可理解范围 → 生成提案;无 → 先追问(D-05);非学习类 → 不适用提示(E-02) | R1、R3、R6 |
| 提案生成 | AI 完成读条目与拆解 | 提案清单呈现(每天 ≤ 1 条,D-11);确认前日程零改动 | R2 |
| 追问答复 | 用户回答「打算学到哪天」(F-01) | 依据答复生成提案;答复不可理解 → E-06 可再答 | R3 |
| 提案确认写入 | 用户删改后确认(D-01 / D-12) | 保留的提案项整单原子转为条目(沿用 AXY-22 模型)+ 资料项落库;原条目不变;两视图即时一致 | R4、R5、R12 |
| 提案重新生成 / 放弃 | 再次发起 / 关闭浮层(D-07 / D-13) | 旧清单被覆盖或消失,日程不变 | R9、R10 |

**负空间**(业务刻意不设的概念——缺失本身是最贵的发现)

| 刻意不设 | 理由 | 依据 |
| ---- | ---- | ---- |
| 对话式 AI 助手入口 | 发起只走条目按钮,不做随手问输入框 | 非目标 #1(D-02) |
| AI 自动发起 | 卡住与否用户自己最清楚,AI 不替用户判断 | 非目标 #2(D-02) |
| 跨度条目数据模型 | AI 按天成条即可表达范围 | 非目标 #3(故事切割判定) |
| 资料收藏 / 评分 / 学习进度 | 资料只随条目留存,进度归执行采集类故事 | 非目标 #4(D-08) |
| AI 服务配置界面 | 服务与模型选型不向用户暴露 | 非目标 #5(D-08) |
| 个人知识库 / RAG | 资料不沉淀,知识库属后续故事 | 非目标 #6(D-08) |
| 提案历史 / 版本 | 重新生成覆盖旧清单,只留当前一份(D-13) | R9、领域模型·提案 |
| 死链检测 / 资料可达性校验 | 可达性由 AI 服务质量保证,系统不做链接校验(D-10) | F-05、边界 |
| 提案条目特殊标记 | 写入条目与手写条目并列展示、无差别标记(日程主人感,D-01) | 边界 #4 |

### 14.2 各演示态契约(可构建级)

**演示态 1 · 发起与提案清单(含重新生成)**
- 入口:登录后工作台承接页进入 `/calendar`(沿用 AXY-22);月视图当日详情条目行「帮我找资料」动作发起(D-06);周视图条目操作卡内同款动作(演示态 1 以月视图为主场景,周视图入口呈现同一浮层);未登录直达按 AXY-22 路由行为 #1 挡回;
- 布局块:页内提案浮层(遮罩 + 居中卡片)→ 来源条目摘要行(条目文字)→ 提案项列表(每条:日期 F-03 + 安排文字 F-02 + 资料项行「标题 F-04 ↗」点击新开页)→ 底部动作条(「确认写入」主按钮 /「关闭」);周视图发起时浮层叠加于网格之上;
- 视觉 / 交互状态:发起后卡片内呈现「正在生成提案…」(R10),期间不可重复发起;确认前 `/calendar` 不新增条目(AC-1);再次发起即重新生成,新清单覆盖旧清单(R9 / D-07);每条提案项行内可编辑文字与日期(F-02 / F-03)、可整条删除;
- 空态 / 边界:来源条目被并行删除时浮层提示后关闭,日程不变;
- 关联 R:R1、R2、R9、R10。

**演示态 2 · 追问一句再出清单(演示专态,WF·R3)**
- 入口:对无可理解时间范围的条目(如仅「学习next框架」)发起;
- 布局块:提案浮层内先呈现追问语「打算学到哪天?」+ 追问答复输入框(F-01)+「继续」/「取消」;
- 视觉 / 交互状态:答复留空提交 → E-01 于输入框下方;答复仍无法理解 → E-06,可再次作答(D-05);有效答复后同演示态 1 出清单;
- 空态 / 边界:取消 → 浮层关闭,日程不变;
- 关联 R:R3。

**演示态 3 · 删改确认与资料留存**
- 入口:演示态 1 清单呈现后,进行删改并确认;
- 布局块:提案项列表(删改操作同演示态 1)→「确认写入」;写入后浮层关闭,回到月视图当日详情 / 周视图网格;
- 视觉 / 交互状态:仅确认保留的条目按各自日期写入,原条目不变,两视图即时一致(R4);写入中「确认写入」置灰;写入失败呈 E-05、日程零新增、浮层保留可重试(R12 / D-12);写入后的条目点开可见资料项行,URL 可点击(R5);
- 空态 / 边界:全部删光后确认 → 视为放弃,浮层关闭、日程不变;
- 关联 R:R4、R5、R12。

**演示态 4 · 不适用与没找到**
- 入口:分别对非学习类条目(如「买牛奶」)与无资料学习条目发起;
- 布局块:提案浮层仅呈现提示区(E-02 / E-03)+「关闭」;E-03 含 AI 给出的理由文字;
- 视觉 / 交互状态:不产出清单、不进入确认动作(R6 / R7);
- 空态 / 边界:关闭后日程不变;
- 关联 R:R6、R7。

**演示态 5 · 服务不可用与重试**
- 入口:AI 服务不可用时发起;
- 布局块:提案浮层呈现 E-04 +「重试」/「关闭」;
- 视觉 / 交互状态:重试即重新发起(R8);恢复后进入演示态 1 流程;
- 空态 / 边界:关闭浮层日程不变;
- 关联 R:R8、R10。
