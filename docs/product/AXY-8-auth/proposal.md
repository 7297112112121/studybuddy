## 2. 目标与背景

刚决定认真学一门课的学生需要一个属于自己的账号，让计划、进度和打卡只认本人，换设备也能接着走（[故事陈述](./story)）。本特性交付手机号注册、手机号/邮箱格式登录、会话与路由守卫的完整闭环，是全部业务故事（AXY-11 信息录入、AXY-12 工作台等）的前置入口。

## 3. 范围与非目标

### 3.1 范围（做什么）

- 登录路由页（`/login`）：手机号/邮箱 + 密码 + 协议勾选，字段级与汇总校验，登录成功进入工作台承接页。
- 注册路由页（`/register`）：手机号 + 密码 + 确认密码 + 协议勾选（验证码字段本期隐藏，D-02），注册即登录并进入工作台承接页。
- 会话管理：退出登录、会话失效、已登录访问登录/注册路由页的回退守卫（见路由行为表）。
- 账号数据与安全：密码不可逆摘要、手机号唯一索引、协议版本与同意时间落库。
- UI 行为与「原型契约」节逐屏一致（登录/注册视图切换、密码可见性、提交中状态）。

### 3.2 非目标（不做什么）

| # | 不做 | 理由 |
| - | ---- | ---- |
| 1 | 短信验证码的发送与校验 | DOR 已声明验证码通道延迟，本期无外部服务依赖；通道就绪后另立迭代恢复字段与校验（D-02） |
| 2 | 找回密码 | 依赖短信验证码通道做身份核验，入口不呈现（占位入口已随 D-08 移除） |
| 3 | 第三方登录（微信登录、手机号一键登录） | 无对接方，入口不呈现（占位入口已随 D-08 移除） |
| 4 | 邮箱注册 | D-07：本期仅手机号注册；登录框仍接受邮箱格式（AC-3），提交后按账号不存在处理 |
| 5 | 《用户协议》《隐私政策》正文内容与法务审阅 | 本期仅落库协议版本与同意时间，协议名为纯文本提及、无链接（D-08） |
| 6 | 2FA、魔术链接、组织等 Better Auth 插件能力 | ADR-0013 约定按需启用，本期不开 |
| 7 | 「记住我」、多端会话管理界面 | 用户故事未涉及 |
| 8 | 企业/高校账号对接 | 线框图品牌区已标注本期不支持 |
| 9 | 新用户信息录入的引导与「跳过」交互 | D-05：建档业务与登录注册业务分离、互不打扰，新用户可录入也可跳过；录入入口的形式归属 AXY-11 / AXY-12 |

## 5. 术语与路由

| 术语 | 含义 |
| ---- | ---- |
| 路由页 | 前端路由页面：`/login`（登录）、`/register`（注册） |
| 工作台承接页 | 登录 / 注册成功后的统一落点页（AXY-12 工作台尚未实现期间的承接，见 D-08、开放问题 #2） |
| 账号 | 数据实体：手机号唯一索引、密码摘要、协议版本与同意时间（见依赖与影响·领域模型） |

### 路由行为表（守卫与跳转的单一事实源）

| # | 触发 | 行为 | 关联 |
| - | ---- | ---- | ---- |
| 1 | 未登录访问任一受保护路由 | 服务端拦截并重定向至 `/login` 路由页；未登录响应不携带受保护页面内容（边界 #6） | R11 |
| 2 | 登录成功 | 进入工作台承接页，不依据建档状态分流（D-03） | R6 |
| 3 | 注册成功 | 自动登录并进入工作台承接页，不强制进入信息录入页（D-04） | R9 |
| 4 | 退出登录 | 回 `/login` 路由页，会话即刻失效（含 Redis 缓存会话）；此后直达工作台承接页地址或浏览器后退均按 #1 挡回；重新登录后原账号与数据完好 | R11 |
| 5 | 已登录访问 `/login` 或 `/register` | 不渲染登录/注册表单；有浏览历史时自动返回上一页；新标签页直接打开（无历史可回退）时进入工作台承接页 | R12 |
| 6 | 页内切换登录 ↔ 注册视图（顶部 tab 与底部链接） | 已填表单值保留、错误提示清除 | R16 |
| 7 | 注册页 E-07 提示中点「去登录」 | 切换到登录视图，且账号框带入该手机号 | R10 |

## 6. 字段与校验规则（F 表）

校验规则的单一事实源；R 条目与原型契约引用 F 编号，不重复正则。

| # | 字段 | 规则 | 违反时 |
| - | ---- | ---- | ---- |
| F-01 | 登录·账号 | 手机号 `^1[3-9]\d{9}$` 或邮箱 `本地名@域名.后缀`；邮箱仅为格式容错、非账号凭据形态（D-06 / D-07） | 留空 → E-01；格式非法 → E-02 |
| F-02 | 密码（登录框、注册框、确认密码框三处规则一致） | 8—20 位且同时含字母与数字（`(?=.*[A-Za-z])(?=.*\d)`） | 违反 → E-03 |
| F-03 | 注册·手机号 | `^1[3-9]\d{9}$`，输入框 `maxLength=11`；账号表唯一索引 | 非法 → E-04；已注册 → E-07 |
| F-04 | 注册·确认密码 | 与密码一致 | 为空或不一致 → E-05 |
| F-05 | 协议勾选 | 必勾（布尔）；勾选与落库（R15）真实生效 | 未勾选提交：表单不提交、勾选框高亮错误态（R4）；错误在勾选框旁呈现、不进汇总计数（D-01） |
| — | 验证码 | 本期从注册表单隐藏（D-02）；短信通道就绪后在注册与找回密码流程中一并恢复，属后续迭代 | — |

## 10. 边界与约束

| # | 边界 | 处理 |
| - | ---- | ---- |
| 1 | 手机号合法范围与输入上限见 F-03 | 前端与后端双重校验，文案见 E-02 / E-04 |
| 2 | 邮箱仅为登录输入的合法形态，本期无邮箱账号（D-06）；邮箱提交走 R7 统一失败文案 | 不做邮箱存在性探测 |
| 3 | 密码规则见 F-02，三处输入框规则一致 | 前端提示 + 后端拒绝 |

**演示态 2 · 校验失败**
