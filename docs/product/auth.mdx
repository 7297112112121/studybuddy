## 故事主干

**作为** 刚决定认真学一门课、还什么都没记录的本科学生，**我想要** 用一个手机号注册出属于我自己的账号，**以便** 计划、进度和打卡只认我一个人，换台设备也能从上次的地方接着走。

## 目标 / 非目标 / 反目标

- **目标**：一个手机号唯一对应一个账号；登录、会话守卫、退出全链路可用。
- **非目标**：注册验证码、第三方登录、找回密码、《用户协议》《隐私政策》正文与跳转（见三桶 ❌）；建档分流（PO 决策 2026-11-14，见修改记录）。
- **反目标**：登录失败时提示「该手机号是否已注册」——账号枚举即使实现更简单也属失败。

## 验收标准（AC）

1. **给定** 手机号 13800138000 已注册且已建学期档案；**当** 填入该手机号与正确密码并勾选协议，点「登录」；**则** 按钮转为「登录中…」且不可重复点击，随后进入「工作台」；不依据是否建档分流 〔走查：演示态 1、3〕
2. **给定** 账号框留空、密码填 a1234567；**当** 点「登录」；**则** 账号字段下方提示「请输入手机号或邮箱」，顶部汇总提示可见，表单不提交 〔走查：演示态 2〕
3. **给定** 账号填 1380013800（10 位）与 abc@mail（无后缀）；**当** 分别点「登录」；**则** 两次都提示「格式不对：手机号 11 位，或 name@mail.com」；改填 13800138000 或 name@mail.com 后该提示消失 〔走查：演示态 2〕
4. **给定** 新手机号 13900139000，密码 abcd1234 且两次一致；**当** 点「注册并进入」；**则** 注册成功，13900139000 成为该账号的登录手机号，自动登录并进入工作台（信息录入为可选，可录入也可跳过）；用同一号码再注册一次则提示「该手机号已注册，去登录」，不产生第二个账号 〔走查：演示态 4〕
5. **给定** 密码输入框分别填 12345678、abcd1234、abcd12345678901234567；**当** 逐次提交；**则** 12345678 与 21 位均提示「密码为 8—20 位，需含字母与数字」，abcd1234 通过校验 〔走查：演示态 4〕
6. **给定** 手机号 13800138000 已注册；**当** 填入该手机号与错误密码，点「登录」；**则** 提示「账号或密码不对」，不提示「密码错误」也不提示该号码是否存在；密码框留空时文案一致 〔走查：演示态 1〕
7. **给定** 13800138000 已登录且处于工作台；**当** 点「退出登录」；**则** 回到登录页；直接输入工作台地址或浏览器后退均被挡回登录页，重新登录后方可进入；退出后再登录，原账号与数据完好 〔走查：行为说明 1〕
8. **给定** 13800138000 已登录且已建学期档案，正处于工作台；**当** 直接输入 /login 或 /register 访问；**则** 不出现登录 / 注册表单，自动回退上一页回到工作台；新标签页直接打开（无历史可回退）时改为进入工作台 〔走查：行为说明 2〕

### 各演示态契约

**演示态 1 · 登录**
- 入口：未登录访问任意页面重定向至此；
- 布局块：品牌区 → 账号输入 → 密码输入 → 协议勾选行（含《用户协议》《隐私政策》占位链接）→「登录」主按钮 → 「去注册」链接 → 第三方登录两占位按钮 →「忘记密码?」占位入口 → 顶部汇总提示条；
- 内容与数据形状：账号（手机号 11 位或 `name@mail.com` 格式）、密码（8–20 位，需含字母与数字）、协议勾选（布尔）；AI 裁定：本期唯一登录凭据为手机号（领域模型仅手机号唯一索引），邮箱只是客户端格式容错——合法邮箱提交按未注册处理返回「账号或密码不对」（与 AC-6 不暴露存在性一致）；
- 交互：当用户账号留空（账号输入框）提交时，系统在字段下方提示「请输入手机号或邮箱」并使顶部汇总可见，以实现账号必填校验（AC-2）；当用户提交 10 位手机号或无后缀邮箱（账号输入框）时，系统提示「格式不对：手机号 11 位，或 name@mail.com」，改合法值后提示消失，以实现账号格式校验（AC-3）；当用户以已注册手机号 + 错误密码或密码留空（密码输入框）提交时，系统统一提示「账号或密码不对」、不暴露号码存在性，以实现凭据错误不泄露注册状态（AC-6）；当用户以合法凭据 + 勾选协议（登录主按钮）提交时，系统把按钮置为「登录中…」并进入演示态 3、随后进工作台，以实现登录状态转移（AC-1）；
- 空态 / 边界：协议未勾选时提交行为见开放问题 #1（AI 提案：阻断并提示）。

**演示态 2 · 校验失败**
- 入口：登录页触发 AC-2 / AC-3 任一校验失败；
- 布局块：与演示态 1 相同，错误提示出现在对应字段下方，顶部汇总提示条可见；
- 内容与数据形状：错误文案逐字如 AC-2 / AC-3 所述；
- 交互：当用户把字段值修正为合法值（账号 / 密码输入框）时，系统即时消除对应提示，以实现校验随输入实时反馈；
- 空态 / 边界：表单不提交、不跳转。

**演示态 3 · 登录中**
- 入口：登录校验通过、请求发出；
- 布局块：与演示态 1 相同，「登录」按钮文案变「登录中…」且置灰不可重复点击；
- 交互：当用户登录请求成功时，系统状态转移进入工作台，以实现登录闭环（AC-1）；当用户登录请求失败时，系统回到演示态 1 并按 AC-6 文案提示，以实现失败可重试；
- 空态 / 边界：期间不可重复提交。

**演示态 4 · 注册**
- 入口：登录页点「去注册」；
- 布局块：手机号输入 → 密码输入 → 确认密码输入 → 协议勾选行 → 「注册并进入」主按钮 → 「返回登录」链接；
- 内容与数据形状：手机号（11 位唯一）、密码与确认密码（8–20 位，需含字母与数字，两次一致）；
- 交互：当用户提交的密码违反规则（密码 / 确认密码输入框）时，系统提示「密码为 8—20 位，需含字母与数字」，以实现密码强度约束（AC-5）；当用户以合法信息点「注册并进入」（主按钮）时，系统注册成功并自动登录进工作台、信息录入可选，以实现注册即登录（AC-4）；当用户以已注册号码再注册（手机号输入框）时，系统提示「该手机号已注册，去登录」且不产生第二个账号，以实现手机号唯一约束（AC-4）；
- 空态 / 边界：无验证码字段（本期从表单隐藏，见占位表）。
