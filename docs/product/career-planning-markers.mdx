## 故事主干

**作为** 已确认目标岗位的本科学生，**我想要** 在课程详情、课程规划选课和课程池筛选时都看见岗位标记，**以便** 从任何入口挑课时都能一眼认出这条职业路线必学的课。

## 目标 / 非目标 / 反目标

- **目标**：岗位标记在三处入口呈现一致，多岗位数据并存时界面只显当前岗位单标记。
- **非目标**：岗位标记的写入 / 更换 / 取消（归 AXY-16）；课程池分组与筛选逻辑本身（归 AXY-9，本故事只加标记统计）。
- **反目标**：一门课同时显示两个岗位标记——即使数据层允许多岗位并存（领域模型），界面违反单标记口径即失败。

## 验收标准（AC）

> 本故事 AC 承接 AXY-16 拆分出的原 AC-8–AC-11（原文不变，编号按本故事重排）。

1. **给定** 已确认「后端开发」；**当** 打开该清单内某课的详情；**则** 「所属岗位」显示「后端开发」标记并说明「当前目标岗位要求学这门课」，另有「「后端开发」的课程清单 · 共 5 门」横向导航且当前课为选中态 〔走查：演示态 1〕
2. **给定** 数据库原理与 SQL 带「后端开发」标记，其先修「数据结构与算法基础」为学习中；**当** 在课程规划选课页查看该课；**则** 标记照常显示；该课置灰不可勾选，并写明「先修未完成：数据结构与算法基础（学习中）」；同页先修已满足的带标记课仍可勾选 〔走查：演示态 2〕
3. **给定** 已确认「后端开发」，课程池共 16 门；**当** 按方向筛选到「前端」；**则** 结果 4 门、其中 0 个岗位标记，分组头写「其中 0 门带岗位标记」；清空筛选后后端 5 个标记仍在 〔走查：演示态 3〕
4. **给定** 课程基础数据中，「程序设计基础（C 语言）」同时出现在后端开发、全栈开发、算法工程师三个岗位的清单里；**当** 依次确认各岗位并查看该课；**则** 该课始终只带当前目标岗位的一个标记，不出现两个岗位标记并存 〔走查：演示态 4〕

### 各演示态契约

**演示态 1 · 课程详情标记态**
- 入口：已确认「后端开发」后打开清单内某课详情；
- 布局块：详情页「所属岗位」行（标记 + 说明「当前目标岗位要求学这门课」）→「「后端开发」的课程清单 · 共 5 门」横向导航条；
- 交互：导航条当前课为选中态，其余 4 门可点击切换（AC-1）；
- 空态 / 边界：非清单内课程的详情不显示所属岗位行，横向导航条随之一并隐藏（渲染条件 = 课程属于当前目标岗位清单——AI 裁定）。

**演示态 2 · 选课页标记透传**
- 入口：课程规划选课页（AXY-13 演示态 1 同一界面），查看带岗位标记的课；
- 布局块：课程卡带岗位标记角标；先修未完成的课置灰并写明缺失先修；
- 交互：标记照常显示于置灰卡（AC-2）；先修已满足的带标记课可正常勾选（AC-2）；本演示态为演示简化——选课页筛选排序行为同课程池（AXY-9），不在本契约复刻；
- 空态 / 边界：无。

**演示态 3 · 课程池标记与筛选计数**
- 入口：课程池（AXY-9 演示态 1）带岗位标记数据；
- 布局块：分组头增加「其中 N 门带岗位标记」统计；
- 交互：筛选到「前端」（4 门、0 标记）→ 分组头写「其中 0 门带岗位标记」；清空筛选 → 后端 5 个标记仍在（AC-3）；
- 空态 / 边界：统计数与实际标记数一致（见 DoD）。

**演示态 4 · 多岗位数据并存**
- 入口：演示数据中「程序设计基础（C 语言）」同时在三个岗位清单里；
- 交互：依次确认后端开发 → 全栈开发 → 算法工程师并查看该课 → 始终只显示当前目标岗位的单个标记，无两标记并存（AC-4）；
- 空态 / 边界：切换岗位后旧标记在新界面零残留（AXY-16 DoD 承接数据层，本故事承界面呈现）。
