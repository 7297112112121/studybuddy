# 完成定义（DoD）通用表

本页是所有用户故事共用的 DoD 通用表，**唯一真源**：故事文档不复制本表，只在各自「完成定义（DoD）」节登记「工作项（本故事特有）」；适用的可选完成项（如性能基线补验）也登记进故事的「工作项」表并标注可选阶段。各阶段推进状态由对应工件（proposal / design / tasks / review）的头部状态行承载，不在故事文档重复。

按研发流程三大部分划分：产品设计、开发落地为必须流程，测试提质为额外流程。**必须段全部满足即达发布门槛；可选段承接测试提质，未完成不阻塞迭代发布。**

## 团队 · 必须完成

| 阶段 | 完成状态 | 验证方式 |
| - | - | - |
| 1 实现完成 | 本故事 AC 全部条目均已实现 | 对照 AC |
| 2 自测通过 | 本故事 AC 逐条执行通过，含 AC 中的异常分支与边界取值 | 逐条打勾的自测记录，注明执行环境与时间 |
| 3 集成验证 | 主链路在开发环境跑通，所依赖服务（数据库、迁移）可用 | 开发环境跑通主链路 |
| 4 评审合并 | PR 构建为绿，AC 走查自核通过，本故事全部代码合入主干且无遗留未合分支 | PR 构建报告与合并记录 |
| 5 端到端验证 | 故事主链路端到端可演示 | CI e2e job 通过 + 按主链路完整演示 |
| 6 质量达标 | 单元与集成测试通过且 CI 为绿 | CI 构建报告 |
| 6 质量达标 | 无阻塞级缺陷，其余缺陷已有处置结论 | GitHub Issues 状态 |
| 7 文档与可交付 | 接口契约与表结构变更已同步更新 | schema.ts 与契约测试（无独立契约 / 表结构文档） |
| 8 验收确认 | PO 按 AC 确认结果，界面与线框图一致 | 读测试执行记录、抽查关键项、演示并逐屏对照原型 |
| 8 验收确认 | 故事状态与验收结果已回写看板，卡片置为完成 | 看板卡片状态 |

## 团队 · 可选完成

承接 proposal 豁免清单与测试提质阶段的验证项。

| 项 | 完成状态 | 验证方式 |
| - | - | - |
| 性能基线补验 | proposal 已豁免的性能要求（Q 条目）达到验收基线（如首屏 ≤ 2s） | 压测记录 / CI 流水线 + e2e 实测记录 |
